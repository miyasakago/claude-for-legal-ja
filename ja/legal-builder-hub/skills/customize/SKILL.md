# /customize

## いつ実行されるか

ユーザーが `/legal-builder-hub-ja:customize` をタイプしました。コールドスタート・インタビュー全体を再実行せず、YAML を手編集せずに、Builder Hub プロファイルの何か — 監視対象レジストリ、更新通知設定、推奨のためのプラクティスエリア — を変更したいと考えています。

## 何をするか

1. **設定を読む。** `~/.claude/plugins/config/claude-for-legal-ja/legal-builder-hub-ja/CLAUDE.md`(と 1 階層上の `~/.claude/plugins/config/claude-for-legal-ja/company-profile.md`)を読みます。プラグイン設定が存在しないか、まだ `[PLACEHOLDER]` 値を含む場合は、次のように言う:

   > まだセットアップを実行していません。まず `/legal-builder-hub-ja:cold-start-interview` を実行してください — customize は既に持っているプロファイルの調整用です。

2. **カスタマイズ可能なマップを表示。** プロファイルの内容をグループ化して、現在の値の 1 行要約と共にリストする:

   - **会社 / 誰か** — 名前、業界、法域、ステージ、practice setting *(12 個のプラグイン横断で共有 — 変更は `company-profile.md` を通じて流れる)*
   - **プラクティスプロファイル** — 対象範囲のプラクティスエリア。コミュニティスキル推奨に使用
   - **インストール済みスターターパック** — ハブ経由でインストールされたプラグインとスキル、インストール元付き
   - **監視対象レジストリ** — ハブがコミュニティスキルを引く GitHub リポジトリ / URL
   - **更新設定** — チェック頻度(daily / weekly / on demand)、通知チャンネル(Slack / セッション内)、自動更新 vs. プロンプト
   - **QA 厳格度** — インストール前に候補スキルに対して `/skills-qa` がどれだけ積極的に問題をフラグするか(lenient / middle / strict)、どの failure mode チェックが有効か
   - **スキルインストールのデフォルト** — インストールスコープ(ユーザー / プロジェクト)、インストール前に `/skills-qa` を自動実行するか
   - **統合** — Slack / 文書ストレージのステータス、フォールバック

3. **何を変更したいか尋ねる。**

   > 何を調整しますか? セクションを選ぶか、自分の言葉で変更を記述してください。

4. **変更を実行。** 現在の値を表示、新しい値を尋ね、下流で何が変わるかを説明、確認、設定に書き込む。

   例:
   - *新規監視レジストリを追加:* 「`/registry-browser` は既存と並んでこのレジストリを検索します。`/auto-updater` は次の実行でチェックします。」
   - *QA 厳格度 strict → middle:* 「`/skills-qa` は同じ所見を報告しますが、確認しない限り中間バンドでインストールをブロックしません。」
   - *自動更新オン → オフ:* 「ハブは更新を自動適用する代わりに、適用前に促します。」

5. **共有プロファイルの変更**(会社名、業界、法域、practice setting、ステージ)では、`~/.claude/plugins/config/claude-for-legal-ja/company-profile.md` に書き、注記する:

   > この変更は 12 個すべてのプラグインに影響します — 法域フットプリントを読むプラグインは今 [new value] を見ます。

6. **締めくくる。**

   > 完了。次の出力には変更が反映されます。他に何かありますか? いつでも `/legal-builder-hub-ja:customize` を実行できます。

## ガードレール

- **セクションを削除しない。** 監視対象レジストリを「削除」したい場合、`[Paused]` とマークすることを提案し、ポーズはインストール履歴を保持しつつ更新チェックを止めることを説明する。
- **内部不整合をフラグ。** 変更によってプロファイルが矛盾する場合(例: 自動更新オン + QA 厳格度オフ、または、インストール済みプラグインのいずれにもマッチしないプラクティスプロファイル)、緊張をフラグする。
- **ガードレール低下をフラグ。** Legal Skill Design Framework チェック(9 つのデザインパラメータ、3 つの法的失敗モード、トラスト表面チェック)は `/skills-qa` が実行するためにあります — オフにするのは目的の敗北です。ユーザーが厳格度を下げたい場合、無効化ではなく中間バンドを推奨。
- **一度に 1 つの変更。** インタビュー全体を再質問しない。
