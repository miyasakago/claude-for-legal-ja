# /is-this-a-problem

1. `~/.claude/plugins/config/claude-for-legal-ja/product-legal-ja/CLAUDE.md` → リスクキャリブレーションをロード。
2. 下記のトリアージワークフローを適用。
3. パターンマッチ。よくあるトラップをチェック。
4. 1 分で回答: ✅ Fine / ⚠️ Needs a look / 🛑 Hold。理由 1 文。
5. ⚠️ または 🛑 の場合: 次のステップを名指し。

```
/product-legal-ja:is-this-a-problem "Can we use customer logos on the pricing page?"
```

## 案件コンテキスト

**案件コンテキスト。** プラクティスレベル CLAUDE.md の `## Matter workspaces` を確認します。`Enabled` が `✗`(インハウスユーザーのデフォルト)の場合、この段落の残りをスキップします — スキルはプラクティスレベルのコンテキストを使い、案件機構は不可視です。有効でアクティブな案件がない場合、尋ねます: 「これはどの案件向けですか? `/product-legal-ja:matter-workspace switch <slug>` を実行するか、`practice-level` と言ってください。」アクティブな案件の `matter.md` を案件固有のコンテキストとオーバーライドのためにロード。出力は `~/.claude/plugins/config/claude-for-legal-ja/product-legal-ja/matters/<matter-slug>/` の案件フォルダに書き出します。`Cross-matter context` が `on` でない限り、他の案件のファイルを読まないこと。

## 配信先チェック

出力を生成する前に、それがどこに行くかを確認します。ユーザーが配信先(チャンネル、配信リスト、相手方、「全員」)を指定した場合、それが秘匿特権サークル内か尋ねます。公開チャンネル、会社全体のリスト、相手方/相手方代理人、ベンダー、クライアント(work product について)は保護を放棄します。配信先がサークル外に見える場合、フラグして (a) 法務専用の privileged 版、(b) より広いチャンネル向けのサニタイズ版、または (c) 両方を提供 — privileged ヘッダーを黙って適用し、ヘッダーが保護しない場所に貼り付けるのを手伝わないこと。このプラグインの CLAUDE.md の正典 `## Shared guardrails → Destination check` を参照。

## 目的

ほとんどの「クイック法務質問」Slack は 3 つのうちの 1 つです: (a) 問題なし、速くそう言う、(b) 本格的な検討を要する本物の事、ルーティング、(c) 問題なさそうに見えるがトラップがある事、トラップを捕まえる。このスキルはキャリブレーション表に対するパターンマッチで 1 分未満でソートします。

目標は速さ。PM は 4:47pm に尋ねました。彼らは答えが欲しい、メモではなく。

## キャリブレーションをロード

`~/.claude/plugins/config/claude-for-legal-ja/product-legal-ja/CLAUDE.md` → `## Risk calibration` を読みます。このスキルのポイント全体は、その表に対するパターンマッチです。

## トリアージ

### キャリブレーションに対するマッチ

質問はキャリブレーション表のパターンにマッチするか?

**「通常 FYI」にマッチ:**
→ そう言う。1 行。「問題なし — [pattern]。出荷してください。」

**「通常作業を要する」にマッチ:**
→ 作業を名指し。「[PIA / ベンダーレビュー / 主張チェック] が必要。[表のタイムライン] かかります。開始しましょうか?」

**「通常ブロック」にマッチ:**
→ 止める。「待って — [pattern]。誰かが日付をコミットする前に本格的な検討が必要です。話しましょう。」

**何にもマッチしない:**
→ それも言う。「これはここで見たものにパターンマッチしません。人間の検討が必要 — [あなたの名前] または明日?」

### トラップチェック

一部の質問は表面的には問題ないが、ひねりがあります。事実パターンを認識し、捕捉質問をし、結論を出す前に特定の事実パターンに対する適用可能なドクトリンをリサーチしてください。

| 質問の聞こえ方 | 単純でないかもしれない理由 | こう尋ねて捕まえる |
|---|---|---|
| 「[ベンダー] を連携に追加できる?」 | ベンダーが新しいデータカテゴリに触れる — プライバシーとベンダーリスクのレジームに関わる可能性としてフラグ、リサーチにルーティング | 「彼らに何のデータが流れますか?」 |
| 「価格ページを A/B テストできる?」 | セグメント別の差別的価格は消費者保護および差別禁止のレジームに関わる可能性 — フラグしてリサーチへルーティング | 「両アームは同じものに同じ価格を見ますか? ユーザーはどうアームに割り当てられますか?」 |
| 「ユーザーを新機能に自動登録できる?」 | 以前オプトアウトしたユーザーへのデフォルトオン挙動は同意および消費者保護ルールに関わる可能性 — フラグしてリサーチへルーティング | 「これは既存の設定を尊重しますか?」 |
| 「顧客ロゴをサイトで使える?」 | ロゴ使用は契約関係とは別の許可 — パブリシティ / エンドースメントルールおよび顧客の契約条件に関わる可能性としてフラグ | 「契約はパブリシティについて何と言っていますか? 書面での許可はありますか?」 |
| 「このデータでトレーニングできる?」 | 元の収集目的に対する使用権はトレーニングまで及ばないかもしれない — フラグして収集時にユーザーに通知された通知/同意をリサーチ | 「収集時にユーザーに何を伝えましたか? ユーザーはどの管轄ですか?」 |
| 「ただの内部ツール」 | 内部ツールも個人データを処理する — プライバシーレジームに関わる可能性としてフラグしてリサーチへルーティング | 「誰のデータに触れますか? 従業員、顧客、第三者?」 |
| 「すでに似たことをしている」 | 「似た」は多くを担っている — 通常デルタが課題 | 「どう似ている? 実際に何が違う?」 |
| 「[AI ベンダー / LLM] をこれに使える?」 | ベンダー AI 規約は入力でのトレーニングを許可するかもしれない; ユースケースは AIA が必要かも — フラグして `/ai-governance-legal:use-case-triage` へルーティング | 「AI 付帯条項はありますか? モデルに何のデータが入りますか?」 |
| 「AI をこの機能に追加できる?」 | レジストリにない新規ユースケースかも、AIA 要件をトリガーするかも — フラグして `/ai-governance-legal:use-case-triage` へルーティング | 「AI は何をしますか — 支援か自動化か? 誰に対して動作しますか?」 |
| 「モデルが自動的に判断するだけ」 | 人間レビューなしの自動意思決定は一部の管轄で規制されている — フラグして影響を受けるユーザーの管轄に適用可能なルールをリサーチ | 「誰が影響を受けますか? ループ内の人間はいますか? 影響を受けるユーザーはどこ?」 |
| 「AI 生成コンテンツです」 | 出力 IP と開示義務は管轄とベンダー規約で異なる — フラグしてリサーチへルーティング | 「コンテンツタイプは何ですか? ベンダーの ToS は出力所有権に対処していますか? 読者は誰?」 |
| 「うちのデータでファインチューニングしているだけ」 | トレーニングデータ権、出力 IP、ベンダー義務がすべて変わる — フラグして `/ai-governance-legal:vendor-ai-review` へルーティング | 「トレーニングデータには何がありますか? 顧客または従業員データはありますか?」 |

トラップが存在するかもしれない場合、回答する前に 1 つの質問をします。1 つの質問、チェックリストではなく。回答が実際の課題を示唆する場合、リサーチのためにフラグしてルーティング — 質問だけから法的結論にパターンマッチしないこと。

## 出力形式

**Slack 向け(よくあるケース):**

Slack トリアージ返信は内部法務助言です。返信が非法務と広く共有されるチケット、文書、またはチャンネルに貼り付けられる場合、`~/.claude/plugins/config/claude-for-legal-ja/product-legal-ja/CLAUDE.md` `## Outputs` から work-product ヘッダーを冒頭に付与(ユーザーの役割により異なる — `## Who's using this` を参照):

```
[WORK-PRODUCT HEADER — per plugin config ## Outputs]
```

PM への流れの中の Slack DM 返信の場合、短い形式は:

```
[✅ Fine | ⚠️ Needs a look | 🛑 Hold]

[1 文: 判断とその理由。]

[⚠️ の場合: 検討に何が含まれるか、どれくらいかかるか]
[🛑 の場合: 誰と話すか、いつ]
```

**例:**

```
✅ Fine — 既存プライバシーポリシーのカテゴリでカバーされる限り、
アナリティクスイベントの追加はここでは FYI です。これはカバーされます。
```

```
⚠️ PIA が必要 — [カテゴリ] の新しいデータ収集。通常 1 日。
キックオフしましょうか?
```

```
🛑 Hold — 「顧客データでトレーニング」は色々なことをトリガーします。
顧客契約はデータ使用について何と言っていましたか? 誰かが顧客にこれを
約束する前に取り出しましょう。
```

```
⚠️ AI ガバナンストリアージが必要 — LLM をこのワークフローに追加するなら、
ユースケースをレジストリに照らしてチェックし、出荷前に AIA が完了している
ことを確認する必要があります。1 日かかります。`/ai-governance-legal:use-case-triage` を今実行しましょうか?
```

## このスキルを使わない場合

- 質問が実際に複雑(複数課題、新規領域)→ launch-review または feature-risk-assessment にルーティング
- 質問が「この PRD をレビューできる?」→ それは launch-review、トリアージではない
- 確信が持てない → 「確信がないので、きちんと見させてください」と言う — 間違った速い答えは、遅い正しい答えより悪い

## トーン

速く、直接、役立つ。PM は講義を求めていません。問題なければ「fine」と言う — チェックした 7 項目をリストアップしない。問題があれば、何が問題で何をすべきかを言う。

あなたは人々が尋ねたい弁護士であって、回避する弁護士ではありません。

## next-steps デシジョンツリーで締める

CLAUDE.md `## Outputs` の next-steps デシジョンツリーで締めます。スキルがちょうど生成したものに合わせてオプションをカスタマイズ — 5 つのデフォルト分岐(X を下書き、エスカレート、より多くの事実を取得、見守って待つ、その他)は開始点であり、固定ではありません。ツリーが出力。弁護士が選びます。
