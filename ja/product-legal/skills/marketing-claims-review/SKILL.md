# /marketing-claims-review

1. `~/.claude/plugins/config/claude-for-legal-ja/product-legal-ja/CLAUDE.md` → マーケティング主張基準をロード。
2. 下記の主張分類とレビューワークフローを適用。
3. すべての主張を抽出。分類: 誇張 / 事実 / 比較 / 含意 / 絶対。
4. 各非誇張主張について: 実証根拠チェック、修正案。
5. 出力: 判断付きの主張別、短ければ修正案を提案。

```
/product-legal-ja:marketing-claims-review
[ランディングページコピーをペースト]
```

## 案件コンテキスト

**案件コンテキスト。** プラクティスレベル CLAUDE.md の `## Matter workspaces` を確認します。`Enabled` が `✗`(インハウスユーザーのデフォルト)の場合、この段落の残りをスキップします — スキルはプラクティスレベルのコンテキストを使い、案件機構は不可視です。有効でアクティブな案件がない場合、尋ねます: 「これはどの案件向けですか? `/product-legal-ja:matter-workspace switch <slug>` を実行するか、`practice-level` と言ってください。」アクティブな案件の `matter.md` を案件固有のコンテキストとオーバーライドのためにロード。出力は `~/.claude/plugins/config/claude-for-legal-ja/product-legal-ja/matters/<matter-slug>/` の案件フォルダに書き出します。`Cross-matter context` が `on` でない限り、他の案件のファイルを読まないこと。

## 目的

マーケティングはプロダクトが最高だと言いたい。法務はそれが真実、または少なくとも証明可能に虚偽でないことを必要とする。このスキルは、競合からの警告書または規制当局からの問い合わせを引き起こす主張を見つけ、エネルギーを保ちながらエクスポージャーを修正する方法を提案します。

## 基準をロード

`~/.claude/plugins/config/claude-for-legal-ja/product-legal-ja/CLAUDE.md` → `## Marketing claims` を読みます:
- 比較主張ポリシー(実証根拠付きで許可 / 抑制 / なし)
- 実証根拠の基準(主張が出荷前に必要なもの)
- よく拒否される主張(歴史から学ぶ)

## コピーをクリアする前に、適用可能な基準をリサーチ

適用可能な管轄とメディアに対して現在運用中の広告・実証根拠基準をリサーチ(例: FTC、NAD(National Advertising Division / 米国広告協議会の自主規制機関)、州 UDAP レジーム(Unfair and Deceptive Acts and Practices / 不公正かつ欺瞞的な行為および慣行)、ヘルスケア / 金融 / 児童プロダクトのセクター規制当局、プラットフォーム固有ポリシー)。*特定の主張*が必要とする実証根拠を特定 — 誰が、いつ、サンプルサイズ、リンゴ対リンゴの基礎 — 単に何らかの実証根拠がファイルにあるかではなく。含意主張と比較主張を高い精査のためフラグ。最新性を検証: エンドースメントおよびレビューガイドは最近更新され、進化を続けています。一次ソースをピンポイント参照で引用。現在の基準を検証できない場合、弁護士検証のためフラグ — 確認していない規則を述べないこと。

> **レビュー中の特定の主張に適用される基準のみを引用してください。** すべての FTC ガイドライン、NAD プラクティスノート、またはセクタールールのブランケットリストは、load-bearing なものを不可視にします。コピーがエンドースメント、推薦文、またはインフルエンサーコンテンツを含まない限り、Endorsement Guides(16 CFR Part 255 / 米国連邦規則集第 16 編 Part 255 のエンドースメントに関する規則)を引用しないこと。資産内の主張がオーバーレイをトリガーしない限り、開示オーバーレイ規則を引用しないこと。コピーがセクターをターゲットまたは関与しない限り、セクター規制当局を引用しないこと。基準は特定の引用された主張にマッピングすることで出力内の地位を獲得します — そうでなければ削除してください。

> **Silent supplement なし。** 構成済み法務リサーチツールへのリサーチクエリが、適用可能な基準(FTC ルール、NAD 決定、州 UDAP、セクタールール、プラットフォームポリシー)についてほとんどまたは何の結果も返さない場合、見つけたものを報告して停止します。尋ねずにウェブ検索またはモデル知識からギャップを埋めないこと。次のように言います: 「検索は [tool] から [N] 件の結果を返しました。[standard / jurisdiction] のカバレッジは薄く見えます。オプション: (1) 検索クエリを広げる、(2) 別のリサーチツールを試す、(3) ウェブ検索 — 結果は `[web search — verify]` でタグ付けされ、依拠する前に発行機関に対して確認すべきです、または (4) 未検証としてフラグして停止。どれにしますか?」弁護士が低信頼度ソースを受け入れるかを決めます。
>
> **ソース帰属の階層化。** すべての引用をソースでタグ付け。モデル知識の引用については、単一のブランケット「verify」タグではなく、3 つの階層のいずれかを使用:
>
> - `[settled]` — 変わっていない可能性の高い、安定した、よく知られた制定法・規制参照(例: FTC Act § 5、Lanham Act § 43(a)(米国商標法 / Lanham Act の §43(a) は虚偽広告等を扱う条項) をコンセプトとして)。コピー承認前に検証するが、優先度は低い。
> - `[verify]` — 実在するが検証すべきモデル知識の引用: 特定の FTC 執行措置、NAD 決定、州 UDAP 制定法、セクター固有ルール、プラットフォームポリシー、判例の保持、閾値、施行日、最近の更新(Endorsement Guides と開示規則は頻繁に更新)。
> - `[verify-pinpoint]` — ピンポイント引用(特定のサブセクション文字、CFR サブパート参照、判例段落番号)は最高の捏造リスクを担い、一次ソースに対して**常に**検証すべき。
>
> ツール取得引用はソースタグを保持(`[Westlaw]`、`[CourtListener]`、`[FTC site]`、`[NAD]`、`[platform policy]`、または MCP ツール名)。ウェブ検索引用は `[web search — verify]` のまま。ユーザー提供引用(実証根拠ファイルから)は `[user provided]` のまま。階層化は実際の検証作業を表面化させます — すべてを検証する読者は何も検証しません。タグを取り除いたり折りたたんだりしないこと。

## 主張分類

下記のカテゴリは、レビューアが認識できるべき構造的パターンです。所定のフレーズが訴訟可能かは、適用可能な管轄で現在運用中の規則、利用可能な特定の実証根拠、オーディエンスに依存します — 結論付ける前にリサーチしてください。

### あいまい / 主観的な主張

測定可能な内容のない主観的アサーション。これらが訴訟可能かは、管轄、コンテキスト、オーディエンスに依存 — 結論付ける前にリサーチ。

| 例 |
|---|
| "The best way to manage your projects"(プロジェクトを管理する最良の方法) |
| "You'll love it"(きっと気に入る) |
| "Revolutionary"(革新的) |

### 具体的な事実主張

測定可能、具体的、合理的な人物が依拠し得るもの。

| 例 | 探すべき実証根拠 |
|---|---|
| "50% faster than [competitor]"(競合より 50% 速い) | ベンチマークデータ、開示された方法論、日付 |
| "Trusted by 10,000 companies"(10,000 社が信頼) | 実数(累積サインアップではなく — *現在*信頼) |
| "Saves 5 hours per week"(週 5 時間節約) | スタディまたは顧客データ、開示されたサンプル |
| "Enterprise-grade security"(エンタープライズグレードのセキュリティ) | それは何を意味する? SOC 2? 明示しなければ約束 |
| "HIPAA compliant"(HIPAA 準拠) | BAA(Business Associate Agreement / 米国 HIPAA における事業提携契約)利用可能、実際にそのように構成 — これは契約上の約束 |

### 比較主張(高い精査)

競合を名指す、または暗示する。クリアする前に、関連管轄とメディアにおける比較広告に適用可能なルールをリサーチ。

| 例 | 修正パターン |
|---|---|
| "Faster than Slack"(Slack より速い) | Slack を名指し、ディフェンドできる直接対決データを使うか、実証根拠付きで「レガシーチャットツールより速い」に抽象化 |
| "The only platform that does X"(X をする唯一のプラットフォーム) | 他に X をする者がいれば虚偽 — 「初のプラットフォーム」(真実なら)または「only」を削除 |
| "[Competitor] can't do this"([競合] はこれができない) | 自社機能を見せる。視聴者に比較させる。 |

`~/.claude/plugins/config/claude-for-legal-ja/product-legal-ja/CLAUDE.md` に従って — 比較主張が「なし」なら、すべてをフラグ。「実証根拠付きで許可」なら、実証根拠をチェック。

### 含意主張

明示されていないが、合理的な読者が推論する。適用可能な広告レジーム下での含意主張の扱いをリサーチ — 含意主張はしばしば明示主張と同じ実証根拠負担を担います。

| 例 | 含意 | 修正 |
|---|---|---|
| "Finally, a secure alternative"(ついに、セキュアな代替) | 競合はセキュアでない | "Finally, security you can verify"(ついに、検証可能なセキュリティ) |
| コンテキストなしの顧客ロゴ | これらの会社が我々を支持 | "Customers include..."(顧客には...)は問題ない; "Trusted by..."(...が信頼)はより多くを含意 |
| "Built for healthcare"(ヘルスケア向け構築) | HIPAA 準拠 | 明確化または修飾 |

### 絶対主張

エラーの余地なし。1 つの反例で虚偽になる。適用可能な管轄で修飾が課題を解決するかをリサーチ。

| 例 | 修正パターン |
|---|---|
| "Never goes down"(決してダウンしない) | "99.9% uptime"(SLA で定義) |
| "100% accurate"(100% 正確) | ベンチマークに紐づく具体的、実証された割合 |
| "Guaranteed"(保証) | 条件付きの保証を実際に提供する場合のみ — これは保証エクスポージャーを生みます |
| "Always" / "Every"(常に / すべて) | "Typically" / "Most"(典型的に / ほとんど) |

## レビュー

### Step 1: すべての主張を抽出

コピーを読む。事実をアサート、比較、または何かを約束するすべての文またはフレーズをリストアップ。リスト内の純粋な誇張は無視。

### Step 2: 分類とチェック

各主張について:

```markdown
**Claim:** "[正確な引用]"
**Type:** [Specific factual | Comparative | Implied | Absolute]
**Substantiation on file:** [Yes — リンク | No | Unknown]
**Call:** [✅ Fine | ⚠️ Needs substantiation | ⚠️ Needs rewording | 🔴 Cut]
**Suggested fix:** "[エネルギーを保つ代替フレーズ]"
**Why:** [1 行]
```

### Step 3: プロダクトに対してチェック

プロダクトはコピーが言うことを実際にするか? 哲学的質問ではなく — PRD をチェックするか PM に尋ねる。

よくあるドリフト: マーケティングコピーは初期仕様から書かれ、プロダクトが変わり、誰もコピーを更新しなかった。

### Step 4: 出力

`~/.claude/plugins/config/claude-for-legal-ja/product-legal-ja/CLAUDE.md` `## Outputs` から work-product ヘッダーを冒頭に付与(ユーザーの役割により異なる — `## Who's using this` を参照)。

```markdown
[WORK-PRODUCT HEADER — per plugin config ## Outputs]

# Marketing Review: [キャンペーン/資産名]

**レビュー日:** [日付]
**資産:** [ランディングページ / メール / 広告 / etc.]

---

## サマリー

[N] 件の主張をレビュー。[N]✅ [N]⚠️ [N]🔴

**Ready to ship:** [Yes | 下記変更で | No — 書き直し必要]

> **「Ready to ship: Yes」を発する前(つまり、外部使用 / 公開のための主張承認):** `~/.claude/plugins/config/claude-for-legal-ja/product-legal-ja/CLAUDE.md` の `## Who's using this` を読みます。役割が Non-lawyer の場合:
>
> > マーケティング主張を公開のために承認することは法的行為です — 公開されると、実証根拠のギャップと比較主張のエクスポージャーは執行または競合チャレンジリスクになります。これを弁護士とレビューしましたか? はいなら進めます。いいえなら、ここに彼らに持っていくブリーフ:
> >
> > [1 ページサマリーを生成: 資産、承認された主張、主張タイプ(具体的事実 / 比較 / 含意 / 絶対)、各々のファイル上の実証根拠、フラグされた含意主張、コピーが公開される前に弁護士に尋ねるべき 3 つのこと。]
> >
> > 弁護士を見つける必要がある場合: あなたの専門規制機関の紹介サービスが最も早い出発点です(米国では state bar、英国・ウェールズでは SRA/Bar Standards Board、スコットランド/北アイルランド/アイルランド/カナダ/オーストラリアでは Law Society、または相当する管轄機関)。
>
> 明示的な「はい」なしに「Ready to ship: Yes」のこのゲートを通り過ぎないこと。「下記変更で」と「No — 書き直し必要」はゲートを要しません — それらはレビュー判断であり、承認ではありません。

## 修正案

[短い資産 — 50 単語未満、またはツイート、ヘッドライン、1 行、タグライン、短い広告 — の場合、このブロックの出力は修正が適用された実際の修正コピーであり、何が変わったかの説明ではない。読者がこのブロックをコピーペーストして資産に入れられるべき。

変更のメタ説明は短い資産には決して許容される出力ではない — 資産が 1 行なら、出力は修正された 1 行**で**あるべき。]
```

## 開示オーバーレイ

下記の事実パターンのいずれかに関わるコピーは、追加の開示レジームの中にあります。適用可能な管轄(プラットフォームポリシーおよびセクター固有ルールを含む)で現在運用中の開示要件をリサーチし、最新性を検証 — これらのレジームは頻繁に更新されます。

- **推薦文 / レビュー** — 話者と広告主の間の物質的関係は通常開示可能 — 現在の形式と配置ルールをリサーチ
- **インフルエンサーコンテンツ** — チャネルとオーディエンスの現在のタグ付け、明確性、目立つこと要件をリサーチ
- **「結果は異なる場合があります」 / 非典型結果** — 表示された結果が代表的でない場合に開示(およびその形式)が要求されるかをリサーチ
- **無料トライアル / 自動更新 / ネガティブオプション** — 自動変換条件の現在の目立つこと、同意要件をリサーチ

## next-steps デシジョンツリーで締める

CLAUDE.md `## Outputs` の next-steps デシジョンツリーで締めます。スキルがちょうど生成したものに合わせてオプションをカスタマイズ — 5 つのデフォルト分岐(X を下書き、エスカレート、より多くの事実を取得、見守って待つ、その他)は開始点であり、固定ではありません。ツリーが出力。弁護士が選びます。

## このスキルが行わないこと

- マーケティングを書かない。何が間違っているかを修正。修正案はエネルギーを保つが、マーケターが声を所有。
- 主張を実証しない。どれが実証根拠を必要とするか、誰がデータを持つかを特定。
- デザインやイメージをレビューしない — 言葉のみ。画像が主張を含意する(競合ロゴに赤い X)場合、フラグしますが、視覚レビューは人間の判断です。
