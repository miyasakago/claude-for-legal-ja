# 8 カテゴリ ローンチレビューフレームワーク

チームが独自のフレームワークを持たない場合のデフォルトフレームワーク。内部プロダクト法務プラクティスから適応。各カテゴリにキーとなる質問と自動スキップ条件があります。

カテゴリは安定したフレーミングコンセプトです。カテゴリ*内*で「Needs work」vs.「Blocker」を構成するものは、適用可能な管轄、セクターレジーム、および `~/.claude/plugins/config/claude-for-legal-ja/product-legal-ja/CLAUDE.md` 内の会社独自のキャリブレーションに依存します。特定の事実パターンが問題であるかないかを結論付ける前に、プロダクトのセクター、オーディエンス、管轄に適用可能な規制レジームをリサーチしてください。

## 1. 契約上のコミットメント

**キーとなる質問:** これは顧客向けの約束と矛盾するか?

チェック: 利用規約、SLA コミットメント、マーケティング資料、顧客契約(特にカスタム条件を持つエンタープライズ MSA)、公開ドキュメント。

**自動スキップ条件:** 顧客向け変更なし — 内部ツール、インフラ、またはユーザーに見えない変更。

**よくある所見:**
- 新機能が ToS の制限と矛盾する
- 新規依存の SLA への影響
- 「含まれる」とマーケティングされた機能が有料ティアに移行

## 2. プライバシー

**キーとなる質問:** 新しいデータ収集、新しい目的、または新しい共有?

チェック: 何のデータに触れるか、それが新しいか既存か、目的が現行プライバシーポリシーでカバーされるか、新しい第三者がそれを見るか。新規通知、同意、または評価が必要かを結論付ける前に、影響を受けるユーザーの管轄に適用可能なプライバシーレジームをリサーチ。

**自動スキップ条件:** データ変更なし — 純粋な UI、新しいロギングのない純粋なインフラ。

**よくある所見:** privacy-legal プラグインの PIA スキルを参照。

## 3. セキュリティ

**キーとなる質問:** 新しい攻撃面?

チェック: 新しいエンドポイント、新しい保管データ、新しいアクセスパス、新しい認証要件。

**自動スキップ条件:** UI のみの変更、バックエンドなし。(ただし、本当に UI のみかをチェック — 新しい API 呼び出しを追加する「UI 変更」は UI のみではない。)

**法務だけの判断ではない** — セキュリティチームを巻き込む。法務の役割はセキュリティレビューが行われたこと、所見が対処されていることを確実にすること。

## 4. IP

**キーとなる質問:** 第三者のコード、コンテンツ、または侵害し得る出力はあるか?

チェック: 新しいオープンソース依存(ライセンス互換性 — 一部のコピーレフトライセンスは独自プロダクトと矛盾する義務を生む; 具体的なライセンスをリサーチ)、第三者コンテンツ(ストック画像、フォント、データセット)、侵害し得るコンテンツを出力する機能(AI 生成、公開表示されるユーザーアップロード)。

**自動スキップ条件:** 新規依存なし、コンテンツ生成なし、ユーザーアップロードなし。

**よくある所見:**
- 新規依存にコピーレフトライセンス
- トレーニングデータの出所が不明
- 通知・テイクダウンプロセスのないユーザー生成コンテンツ — 適用可能な safe-harbor レジームをリサーチ

## 5. 第三者との相互作用

**キーとなる質問:** 新しいベンダー、パートナー、または連携?

チェック: 契約があるか、データが流れる場合の DPA があるか、第三者の失敗が私たちの問題か(稼働時間、セキュリティ)。

**自動スキップ条件:** 新規外部当事者なし。

**よくある所見:**
- DPA のない新規ベンダー
- 異なるデータプラクティスを持つ連携パートナー
- SLA のない API 依存

## 6. 規制 / セクター固有

**キーとなる質問:** これは規制セクター、オーディエンス、または管轄に触れるか?

プロダクトのセクター(例: 健康、金融サービス、児童と学生、保険、通信、雇用、広告)、オーディエンス、管轄(米国連邦、米国州、EU、英国、プロダクトが到達する他の地域)に適用可能な規制レジームをリサーチ。該当する場合、アクセシビリティおよび輸出規制レジームも検討。一次ソースをピンポイント参照で引用し、最新性を検証 — 規制セクターと管轄は頻繁に変わります。

**自動スキップ条件:** 既存プロダクトと同じユーザー、同じセクター、同じ管轄 — 規制スコープに新しいものはない。

**よくある所見:**
- 規制セクターへの、レジームが要求する支援インフラ(契約、コントロール、開示)なしの拡大
- 規制オーディエンス(例: 児童)が、適用可能なレジームが要求する保護なしに使い得る機能
- ローカリゼーション、ライセンス、または通知要件のある管轄への国際展開

## 7. マーケティング主張

**キーとなる質問:** 実証根拠を要する主張はあるか?

marketing-claims-review スキルを参照。

**自動スキップ条件:** マーケティングコンポーネントなし — サイレントローンチ、内部機能、フラグフリップ。

## 8. AI ガバナンス

**キーとなる質問:** これは任意の形式の AI を使うか? ユースケースはレジストリにあるか? AI 影響評価が完了しているか? ベンダー AI 規約はレビューされているか?

チェック: 第三者モデル、内部構築モデル、AI 駆動のベンダー機能、自動スコアリングまたは分類、生成コンテンツ、推薦、予測。影響を受けるユーザーの管轄とユースケースタイプに適用可能な AI ガバナンスレジームをリサーチ — AI 固有のルールは進化しており、地域とセクターで実質的に変わります。

**自動スキップ条件:** AI コンポーネント検出なし。

**よくある所見:**
- AI レジストリにないユースケース
- 入力でのトレーニングを許可するベンダー AI 規約
- 人間がループに必要かもしれないところ、人間ループ設計のない自動意思決定
