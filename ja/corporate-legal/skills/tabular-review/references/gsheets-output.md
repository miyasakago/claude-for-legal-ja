# Google Sheets 出力仕様

Google Workspace のチーム向け。Excel 出力と同じ構造、異なるメカニクス。Excel と Sheets 両方のパスが利用可能なら、ユーザーにどちらを好むか尋ねる — 環境から推測しない。

## どう書くか

3 パス、推奨順:

1. **Google Sheets MCP**(`gdrive` または `gsheets` MCP で書き込み / 作成機能が接続済みなら)。スプレッドシート作成、シート書き込み、API でフォーマット設定。
2. **Google Sheets API via ADC**(ユーザーが `gcloud auth application-default login --enable-gdrive-access` をセットアップし Python `google-api-python-client` が利用可能なら)。`sheets.spreadsheets().create()` と `batchUpdate` でフォーマット。
3. **フォールバック:CSV + 手動インポート。** CSV を書き、ユーザーに Sheets にインポートするよう伝える。色分けとデータ検証を手動適用できるよう `format-instructions.md` も書く。

未検証の書込アクセスを仮定しない。先にチェック、優雅にフォールバック。

## ワークブック構造

Excel 仕様を正確にミラー — 同じシート、同じセマンティクス、Sheets ネイティブメカニクス:

**Sheet: `Review`**(メイングリッド)
- Row 1: Work-product ヘッダー(マージセル)
- Row 2: 列ラベル
- Row 3+: 文書あたり 1 行
- Column A: 文書名 / リンク(ソース文書が Drive にあればファイルへのハイパーリンク — Excel に対する Sheets の利点)
- Column B 以降:スキーマ列ごとに 1 列
- **ソース引用はセルノートに**(Sheets ノート、コメントではない — ノートは永続注釈、コメントはコラボレーションスレッド)。ノートはホバーで表示され、`.xlsx` にエクスポートするとコメントに。
- 状態でセル塗りつぶし:デフォルト = `answered`、薄黄 = `unclear` または `needs_review`、薄灰 = `not_present`。`batchUpdate` の `repeatCell` と `userEnteredFormat.backgroundColor` を使用。
- 各グループ後の `Verified` 列:デフォルトは空、`setDataValidation` 経由でデータ検証ドロップダウン `✓ | ✗ | ?`。

**Sheet: `Flags`**
- Excel 仕様と同じ。フラグセルあたり 1 行。

**Sheet: `_schema`**
- `.review-schema.yaml` の列定義。

**Sheet: `_summary`**
- カウント、フラグされた列、検証リマインダー。

## 使うべき Sheets 固有の利点

- **ソース文書へのハイパーリンク。** レビュー対象文書が Drive にあれば(VDR エクスポートと社内リポジトリでよくある)、各行の文書名はファイルへのハイパーリンクであるべき。これはクリックトゥソースパターンで、Sheets はネイティブに行う。
- **共有レビュー。** Sheets はローカル `.xlsx` より同時レビューを上手く処理。ディールチームが検証作業を分割したいならこのフォーマット。
- **スキーマの名前付き範囲。** 各列に名前付き範囲を定義し、下流の式(ピボットテーブル、条件付きカウント)を読みやすくする。
- **状態列による条件付き書式。** データ列ごとに隠し `_state` 列を書けば、条件付き書式ルールで色分けを駆動可能 — セル単位書式よりクリーンで、ソートに耐える。

## Sheets 固有の落とし穴

- **ノートはセル単位で印刷時不可視。** 出力がパートナーミーティング用に印刷または PDF 化されるなら、`Flags` シートにも引用を書いて生存させる。
- **Sheets は 1000 万セル制限。** 法務レビューでは到達しないが、誰かが 50,000 文書 × 30 列 + ソース列をグリッド化しようとしたら警告。
- **共有デフォルト。** プラグインのプラクティスプロファイルに従えば、これは弁護士成果物。スプレッドシートは制限付き共有(オーナーのみ)で作成し、ユーザーに意図的に共有するよう伝える。「リンクを知る全員」をデフォルトにしない。
- **数式エスケープ。** verbatim 引用が `=`、`+`、`-`、または `@` で始まれば、シングルクオート(`'`)を prefix して Sheets が数式としてパースしないようにする。これは実失敗モード:"- The parties agree..." で始まる契約条項はエスケープなしでは数式エラーとしてレンダリングされる。

## してはいけないこと

Excel 仕様と同じ:信頼度パーセンテージなし、引用切り詰めなし、データ領域のセルマージなし、必ず `_schema` と `_summary` シートを書く。


## Formula injection 対策

Excel、Sheets、CSV 出力でセルを書き込む前に、formula injection を無害化する。相手方由来テキスト(契約引用、当事者名、登録代理人データ、CLM エクスポート)は攻撃者制御。`=`、`+`、`-`、`@`、`	`、``、または `
` で始まるセルは数式として解釈されるか、行構造を壊す。

- **シングルクオートで prefix:** `'=SUM(A1:A10)` → `=SUM(A1:A10)`(実行されずテキストとして表示)
- **文書、ツール結果、ユーザー貼り付けからのテキストを含むすべてのセルに適用。** あなたが制御するカラムヘッダーと生成する計算値は安全。
- **CSV: 埋め込みコンマ、ダブルクォート、改行もエスケープ**(RFC 4180 quoting)。
- これはオプションではない。マクロをトリガーするか DDE 経由でデータを exfiltrate するスプレッドシートをユーザーが Excel で開く事態は、ユーザーへのサプライチェーン攻撃。
