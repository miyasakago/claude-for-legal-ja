# Stakeholder Summary

## 案件コンテキスト

**案件コンテキスト。** プラクティスレベル CLAUDE.md の `## Matter workspaces` を確認。`Enabled` が `✗`(インハウスユーザーのデフォルト)であれば、この段落の残りはスキップ — スキルはプラクティスレベルのコンテキストを使い、案件機構は不可視。有効でアクティブな案件がなければ尋ねる:「これはどの案件のもの? `/commercial-legal-ja:matter-workspace switch <slug>` を実行するか `practice-level` と言ってください。」アクティブな案件の `matter.md` を案件固有のコンテキストとオーバーライドのためにロード。出力は `~/.claude/plugins/config/claude-for-legal-ja/commercial-legal-ja/matters/<matter-slug>/` の案件フォルダに書き込む。`Cross-matter context` が `on` でない限り、他の案件のファイルを読まない。

---

## 宛先チェック

出力前に、どこに行くかを確認。ユーザーが宛先を指定した場合(チャンネル、配信リスト、相手方、「全員」)、それが秘匿特権サークル内かを尋ねる。公開チャンネル、全社配信リスト、相手方/相手方代理人、ベンダー、クライアント(work product については)は保護を放棄させる。宛先がサークル外に見える場合、フラグして提供:(a) 法務のみの秘匿特権版、(b) 広範なチャンネル用のサニタイズ版、(c) 両方 — 秘匿特権ヘッダーを黙って適用してから、それが保護しない場所への貼り付けを助けない。このプラグインの CLAUDE.md の正本 `## Shared guardrails → Destination check` を参照。

## 目的

この契約を求めたビジネスオーナーは法務メモを望んでいない。彼らが知りたいのは:署名できるか、何が落とし穴か、何をする必要があるか。このスキルは完成したレビューを取り、それに変換する。

## どちらのサイドか?

下敷きのレビューメモは、セールスサイドかパーチェシングサイドのいずれかのプレイブックで実行された。そのフレーミングを通す。パーチェシングサイドのサマリーは、ビジネスオーナーに「私たちが得るものと、譲ったもの」を伝える。セールスサイドのサマリーは、「私たちが売るもの、私たちが負うもの」を伝える。レビューがどちらのサイドで実行されたかを確認し(レビューメモの冒頭に書かれているはず)、声を一致させる。メモから明らかでなければ、要約前に弁護士に尋ねる。

## オーディエンスのキャリブレーション

`~/.claude/plugins/config/claude-for-legal-ja/commercial-legal-ja/CLAUDE.md` → `## House style` → 誰がステークホルダーサマリーを読むか、どれくらい長くすべきか、を読む。指定されていなければ、デフォルト:調達または部門長、最大 2 段落、法律術語なし。

異なるオーディエンスは異なるサマリーを必要とする:

| オーディエンス | 関心事 | 関心がないもの |
|---|---|---|
| **調達** | 価格、更新メカニクス、承認振り分け | 責任上限の構造 |
| **部門長(予算オーナー)** | チームが使えるか、壊れた場合に何が起きるか、コスト | 補償の範囲 |
| **財務** | 総保有コスト、更新価格リスク、簿外コミットメント | 準拠法 |
| **セキュリティ/IT** | データ取り扱い、副処理者、SOC 2、データがどこにあるか | それ以外すべて |
| **役員スポンサー** | これは恥をかかせるか、法務はブロッカーか | 詳細 |

文脈から明らかでなければ、誰のためかを尋ねる。

## サマリー

### 長さの上限 — 強制

サマリーは:
- **1 段落**:判断と何であるか(ビジネス用語、平易な英語)
- **1 段落**:落とし穴 — 誰も今教えなければステークホルダーが後で驚くこと
- **2〜3 項目のチェックリスト**:ステークホルダーが実際にすべきこと(最大 3 項目。4 項目目を入れたいなら、最初の 3 つが締まっていない)
- **1 行のクロージング**:承認のタイミング

**合計 200 ワード未満。** それ以上書いているなら、ステークホルダーに不要な詳細を含めている — 彼らにはメモがある。これはステークホルダーが返信を打つ前のクイックリードである。

クロージングに 3 段落目が必要なら、代わりにチェックリストに畳み込む。クロージングを 4 つ目のブロックに育てない。

### 引用の範囲 — 規律

契約条項を引用するとき(サマリー内、「落とし穴」段落内、またはチェックリスト内)、**完全な条件文**を引用し、切り詰めない。"Except as expressly provided in the Order Form, renewal of promotional or one-time priced subscriptions resets to list price" と読める条項は、"renewal resets to list price" とは異なる意味になる — 切り詰めると条件が落ち、条項が何をするかを誤って表現する。

完全な条件引用がサマリーの長さ上限に収まらなければ、切り詰めるのではなく言い換える。「For promotional pricing, renewal resets to list」は公正な言い換え。「renewal resets to list」は違う — 例外を規則に格上げしてしまう。

### 形式

`~/.claude/plugins/config/claude-for-legal-ja/commercial-legal-ja/CLAUDE.md` の `## Outputs` から作成物ヘッダーを先頭に付ける(ユーザー役割によって異なる — `## Who's using this` 参照)。

```markdown
[WORK-PRODUCT HEADER — プラグイン設定の ## Outputs に従って]
<!-- 法務秘匿特権サークル外(ビジネスステークホルダー、相手方、ベンダーなど)に転送する場合、上記のヘッダーを削除してください。転送前に管轄および案件に合った正しいマーキングを確認してください。 -->

**[相手方] [契約タイプ]** — [READY TO SIGN | NEEDS CHANGES | BLOCKED]

[1 段落:この契約が何をするか、ビジネス用語で。「クラウドベース分析サービスを提供する Master Services Agreement」ではなく — 「マーケティングチームが望んでいるダッシュボードツールの契約」。]

[1 段落:ステークホルダーが知る必要があること。あるなら落とし穴。
誰も今教えなければ後で驚くこと。例:「ご注意:毎年自動更新で、
60 日前に解約する必要があります。トラッカーに追加しましたが、
知っておくべきです。」 または:「クリーンな契約、驚きなし、署名可」。]

<!-- `renewal-tracker` が実際にこの契約について実行されていない限り「トラッカーに追加しました」と主張しないでください — 下記の「トラッカーエントリを主張する前に検証」を参照。 -->

**トラッカーエントリを主張する前に検証。** サマリーが「トラッカーに追加した」(または同等 — 「トラッカーに登録」「追跡中」「リマインダー設定」)と言う前に、この契約について `renewal-tracker` が実行されたことを確認する。出力フォルダまたは案件フォルダで、この相手方/契約を名指す `renewal-tracker` 出力をチェック。なければ:

- まずこの契約について `renewal-tracker` を実行し、その後サマリーを書く。
- またはトラッカーエントリを主張せずにサマリーを書き、アクション項目を含める:「更新トラッカーに追加 — まだ未実施。」

トラッカーエントリが存在すると主張するのは、存在しないより悪い。ステークホルダーは発火しないリマインダーを信頼してしまう。真実の発言が「追跡中」であれば、スキルがトラッカーを実行する。「カレンダーに追加してください — 私はログしていません」なら、それを言う。

**することは:**
- [ ] [アクション項目があれば — 「データが EU にあることがチームで OK か確認」または「何もなし — 署名へ振り分けます」]

**承認:** [誰が承認、予想タイミング]
```

### 何を翻訳するか

| 法的発見 | ビジネスへの翻訳 |
|---|---|
| 「責任は 12 か月の手数料に上限」 | 「彼らが何かを壊した場合、回収できる最大は私たちが支払った 1 年分です。」 |
| 「任意解除なし」 | 「一度署名したら、全期間ロックインされます — 使わなくなってもキャンセルできません。」 |
| 「60 日通知付きの自動更新」 | 「毎年自動更新です。キャンセルするには更新日の 2 か月前に伝える必要があります。」 |
| 「IP 補償なし」 | 「このツールが特許を侵害していると訴えられた場合、ベンダーは私たちを防御する義務がありません。」 |
| 「副処理者リスト非開示」 | 「彼らを通して私たちのデータにアクセスできる他の会社が分かりません。」 |
| 「解除後 30 日以内のデータ削除」 | 「キャンセルすると、彼らは 1 か月以内に私たちのデータを削除します。必要なものは事前にエクスポートしてください。」 |
| 「SLA クレジットは月額料金の 10% に上限」 | 「サービスがダウンすると、小さなクレジットが戻ります。ビジネスへのダウンタイムコストはカバーしません。」 |

### 含めないもの

- セクション番号
- 引用符で囲まれた定義語
- "indemnification" という単語(「彼らが補償する場合は…」「私たちが補償する場合は…」と言う)
- "notwithstanding" という単語
- 色付きドット付きのリスクマトリクス(このステークホルダーが以前に明示的に求めていない限り)
- 「これは法的助言ではない」という但し書き — ステークホルダーは誰が送ったかを知っている

## レビューが問題を見つけた場合

レビューに 🔴 または 🟠 の論点があれば、サマリーは依然として 2 段落である必要 — ただし 2 段落目は「私たちが押し戻している内容とその理由」になる。

```markdown
[WORK-PRODUCT HEADER — プラグイン設定の ## Outputs に従って]
<!-- 法務秘匿特権サークル外に転送する場合、上記のヘッダーを削除。 -->

**[相手方] [契約タイプ]** — NEEDS CHANGES

[何であるか、1 段落。]

これが準備できる前に [N] 件について彼らに戻ります。主なもの:
[平易な英語での重大論点 — 「彼らは私たちのデータを使って自社製品を改善する権利を望んでいます。
これは私たちの競合のインスタンスが私たちのデータから賢くなることを意味します」]。
それを削除するよう求めました。[現実的な評価:「おそらく同意するでしょう」/
「これが膠着点になるかもしれません — 報告します」]。

**することは:**
- [ ] まだ何もなし — 彼らから戻り次第お知らせします。
  または
- [ ] [彼らが下す必要のあるビジネス判断:「彼らが X で動かないなら、Y で OK か、
  それとも撤退か?」]
```

## ハンドオフ

**vendor-agreement-review / saas-msa-review から:** これらのスキルが完全なメモを生成。このスキルはメモを読んで圧縮する。契約を再レビューしない — レビューを読む。

**ステークホルダーへ:** `~/.claude/plugins/config/claude-for-legal-ja/commercial-legal-ja/CLAUDE.md` が示すチャンネル経由で。Slack なら 150 ワード未満。メールなら上記形式そのままで OK。

## エスカレーション・ファンアウトの突合

上流のレビューは 1 対多のプロデューサー:異なる発見について 5 つのエスカレーション対象(Deputy GC、CISO、Privacy Officer、CFO、ビジネスオーナー)を指名できる。`escalation-flagger` は 1 つの発見を一度に振り分け。突合ステップなしには、Deputy GC がメモを見て、他の 4 人の承認者は見ない。

サマリーを生成する前に、上流のレビューメモを読んでエスカレーションを集計:

1. **レビューが指名したエスカレーション対象をカウント。** レビューの末尾にあるルーティング/エスカレーションブロック、または発見ごとの「[X] にエスカレーション」タグを探す。承認者名で重複排除 — 2 つの発見に指名されたレビューアーは 1 回としてカウント。
2. **実際にルーティングされたエスカレーションをカウント。** レビューフォルダ(または案件フォルダ)で、レビューが書かれて以降に `escalation-flagger` が生成した `escalation-*.md` ドラフトを読む。各ドラフトは 1 人の承認者を指名。
3. **突合。** N 人の承認者が指名され M 件のドラフトがあれば、(N − M) 件のエスカレーションがルーティングされていない。

サマリーに短い突合ブロックを含める — チェックリストの上、落とし穴段落の下に:

```markdown
**エスカレーション・ステータス:** [N] 件中 [M] 件のエスカレーション対象をルーティング済み。以下はまだルーティングされておらず、対応が必要:
- [承認者名] — [指名した発見について 1 行]
- [承認者名] — [1 行]
```

すべての N がルーティング済みなら:
```markdown
**エスカレーション・ステータス:** [N] 件中 [N] 件のエスカレーション対象をルーティング済み。
```

上流のレビューがエスカレーションを発生させなかった場合、ブロックを省略。

**ステークホルダーが名前を認識しないからといって、指名された承認者を突合から省略しない。** ビジネスステークホルダーはしばしば Privacy Officer や CISO が誰かを知らない。突合は内部向け — サマリーを送る弁護士にすべてのルーティングが完了しているかを伝え、ステークホルダーには伝えない。ステークホルダー向けのサマリーを狭く保つ必要があれば、突合は「ルーティングステータス」フッターまたは添付メモに置ける — しかし存在する必要がある。ルーティングが完了したと示唆しているのに完了していないサマリーは、サマリーなしより悪い。

**ワードカウントのカーブアウト。** エスカレーション突合ブロックは 200 ワード上限から免除。サマリー本文での長さ上限の規律は維持 — 突合は事務であり、物語ではない。

**escalation-flagger ドラフトが存在しないとき。** 上流のレビューが承認者を指名し、フォルダにドラフトがない場合、M = 0 として扱う。突合ブロックはすべての N を未ルーティングとして列挙。それが発見。

## トーンに関する注記

ステークホルダーは法務について 2 つのことを覚える:それは私をブロックしたか、それは意味をなしたか。このスキルは法務が意味をなす方法。コーヒーを飲みながら賢い同僚に説明するように書く — ファイル用メモを書くようにではなく。

正直なサマリーが「これは大丈夫、署名して」なら、それを言う。徹底しているように見せるためにクリーンなレビューを 3 段落に詰めない。
