# /escalation-flagger

`~/.claude/plugins/config/claude-for-legal-ja/commercial-legal-ja/CLAUDE.md` のエスカレーションマトリクスに従って契約論点の承認者を特定し、メッセージを起草します。これで 5 時に「ちょっといいですか」を書かなくて済みます。

## 指示

1. **`~/.claude/plugins/config/claude-for-legal-ja/commercial-legal-ja/CLAUDE.md`** → Escalation 節をロード。欠落している場合はその旨を伝え — プラクティスプロファイルの編集が必要です。

2. **論点を特徴づける:**金額閾値 / 条項乖離 / 自動トリガー / ビジネス判断。

3. **マトリクスに照合し、承認者を特定。** 具体的に — 「リーガル幹部」ではなく、人物または役職で。

4. **下記テンプレートに沿って依頼文を起草:**契約の内容、プレイブックの内容、選択肢と推奨、判断期日。

5. **送信しない。** 起草し、表示し、弁護士に送信させる。

## 例

```
/commercial-legal-ja:escalation-flagger
Acme の MSA に無上限の責任があります — 誰が承認し、何と伝えれば?
```

```
/commercial-legal-ja:escalation-flagger
Reference: acme-review-memo.md
Issue: §8.2 補償カーブアウト
```

## 案件コンテキスト

**案件コンテキスト。** プラクティスレベル CLAUDE.md の `## Matter workspaces` を確認。`Enabled` が `✗`(インハウスユーザーのデフォルト)であれば、この段落の残りはスキップ — スキルはプラクティスレベルのコンテキストを使い、案件機構は不可視。有効でアクティブな案件がなければ尋ねる:「これはどの案件のもの? `/commercial-legal-ja:matter-workspace switch <slug>` を実行するか `practice-level` と言ってください。」アクティブな案件の `matter.md` を案件固有のコンテキストとオーバーライドのためにロード。出力は `~/.claude/plugins/config/claude-for-legal-ja/commercial-legal-ja/matters/<matter-slug>/` の案件フォルダに書き込む。`Cross-matter context` が `on` でない限り、他の案件のファイルを読まない。

## 目的

すべての契約チームには、書かれているかどうかは別として、エスカレーションマトリクスがあります。このスキルは書かれているもの(`~/.claude/plugins/config/claude-for-legal-ja/commercial-legal-ja/CLAUDE.md` 内)を読み、契約論点をそれに照合し、承認者を特定し、依頼文を起草します — 弁護士が 5 時に「ちょっといいですか」メッセージを書かなくて済むように。

## マトリクスをロード

**どちらのサイドか?** マトリクスに照合する前に、エスカレーション対象の契約について自社がどちらのサイドかを判定。通常は明らか:相手方が物品・サービスを提供するベンダー/サプライヤーなら、自社はパーチェシングサイド。相手方が自社の製品/サービスを買うカスタマーなら、セールスサイド。明らかでなければ尋ねる。該当するプレイブック節(`### Sales-side playbook` または `### Purchasing-side playbook`)を読み、その条項がフォールバック範囲内か、自動エスカレーションをトリガーするかを評価 — 片方のサイドで問題ない条項が、もう片方では絶対拒否ということがある。起草した依頼文にどちらのサイドが適用されたか記載し、承認者がどのプレイブックが適用されたかを分かるようにする。

`~/.claude/plugins/config/claude-for-legal-ja/commercial-legal-ja/CLAUDE.md` → `## Escalation` を読みます。欠落しているか曖昧であれば、その旨を伝え — コールドスタート・インタビューがこれを捕捉すべきで、もしされていなければプラクティスプロファイルの編集が必要です。

期待される構造:

| Can approve | Threshold | Escalates to | Via |
|---|---|---|---|
| Paralegal | 標準条項、<$50K | Counsel | Slack |
| Counsel | 非標準だがフォールバック範囲内、<$500K | GC | Slack または email |
| GC | それ以外すべて | CFO/Board | Meeting |

加えて、**自動エスカレーション・トリガー** — 金額にかかわらずエスカレーションされる事項。典型的には:無上限の責任、IP 譲渡、「絶対拒否」リスト上のあらゆるもの。

## ワークフロー

### Step 1: 論点を特徴づける

何がエスカレーションされるか?

- **金額閾値:** 契約価値がある人の承認権限を超えている
- **条項乖離:** ある条項がプレイブックのフォールバック外 — それを許容するかをより上位者が決める必要がある
- **自動トリガー:** 必ずエスカレーションする事項のいずれかが存在
- **ビジネス判断:** 法的判断ではない — リーガル幹部ではなくビジネスオーナーが必要

実際には問題ないものをエスカレーションしない。条項が `~/.claude/plugins/config/claude-for-legal-ja/commercial-legal-ja/CLAUDE.md` のフォールバック範囲内であれば、上に上げる必要はない。

### Step 2: マトリクスに照合

```
論点は自動トリガーか?
  → YES: そのトリガーに指定された人物にエスカレーション
  → NO: 続行

契約価値はレビューアーの閾値を超えるか?
  → YES: その金額レベルで権限を持つ人物にエスカレーション
  → NO: 続行

条項乖離はすべての文書化されたフォールバック外か?
  → YES: 非標準条項を承認できる人物にエスカレーション
  → NO: レビューアーが承認できる — エスカレーション不要
```

### Step 3: 承認者を特定

具体的に。「リーガル幹部にエスカレーション」ではなく、`~/.claude/plugins/config/claude-for-legal-ja/commercial-legal-ja/CLAUDE.md` から人物または役職を名指し。マトリクスがこの状況をカバーしていなければ、その旨を伝える:「エスカレーションマトリクスは [状況] をカバーしていません。これを所管する [GC 名] に確認することを提案します。」

### Step 4: 依頼文を起草

承認者は、メッセージだけで判断できるべき — 「契約を引っ張ってきます」ではなく。

```markdown
**Escalating to:** [名前]
**Via:** [Slack #channel / email / meeting — `~/.claude/plugins/config/claude-for-legal-ja/commercial-legal-ja/CLAUDE.md` に従って]
**Urgency:** [期限があれば]

---

Hey [名前] —

[相手方] [契約タイプ] の判断をお願いします。[取引コンテキストを 1 文で。]

**論点:** [平易な言葉で、1 段落。彼らが何を望むか、それがなぜ自社の標準から外れているか、リスクが実際に何か。]

**契約の文言:**
> "[厳密な引用]"

**プレイブックの文言:** [`~/.claude/plugins/config/claude-for-legal-ja/commercial-legal-ja/CLAUDE.md` からの引用]

**選択肢:**
1. **Accept** — [なぜ許容しうるかを 1 行]
2. **Push back with:** "[提案する対案文言]" — [相手方の予想される反応を 1 行]
3. **Walk** — [ビジネス文脈を踏まえて現実的か 1 行]

**推奨:** [どの選択肢か、簡潔に理由]

**期日:** [期限があれば日付]

[完全なレビューメモへのリンク]
```

### Step 5: エスカレーションを記録

チームがチケットシステムまたは [CLM] 承認ワークフローを使うなら、それにログ。使わないなら、レビューメモにエスカレーションが送られたこと、誰に、いつ送られたかを記載。次にメモを読む人にはステータスが見える。

## キャリブレーション:迷ったら注釈付きでエスカレーション

不要なエスカレーションのコストは、承認者の時間 30 秒程度 — 読んで「OK、進めて」と言い、見たという記録が残ります。エスカレーション漏れのコストは、未承認条項に署名すること、すなわち一方通行ドアです。コストは非対称です。**迷ったらエスカレーション。**

何をエスカレーションの対象とするかのキャリブレーションは、このスキルではなく `~/.claude/plugins/config/claude-for-legal-ja/commercial-legal-ja/CLAUDE.md` に存在します。プレイブックの明示的立場、フォールバック、「金額にかかわらず自動エスカレーション」リストをチェック:

- **明らかにフォールバック範囲内:** エスカレーション不要。
- **明らかに範囲外、または自動エスカレーションリスト上:** エスカレーション。
- **不確実 — 条項が曖昧、新規、または論理的に範囲内とは言えるが苦しい:** いずれにせよエスカレーションし、不確実性を明示的に注記。ドラフトは承認者が判断すべき具体的な質問と、なぜスキルがそれをフォールバック範囲内と確信できなかったかをフラグする。承認者が絞り込み、スキルは絞り込まない。

過剰なエスカレーションが承認者を流し読みさせる訓練になるかもしれないからといって、エスカレーションを抑制してはならない。それは承認者体験の問題であり、弁護士がプレイブックの閾値を調整して解決する問題 — スキルが不確実な条項について主観的判断を下して解決する問題ではない。

プレイブックが扱っていない条項が出てきた場合、閾値を推測せず — レビューする弁護士にこの種の論点をエスカレーションすべきか尋ね、回答を `~/.claude/plugins/config/claude-for-legal-ja/commercial-legal-ja/CLAUDE.md` に記録するよう提案して、今後のレビューが一貫するようにする。

## このスキルが行わないこと

- 承認しない。振り分けるだけ。
- 選択肢の間で判断しない。ドラフトは推奨を含むが、承認者が判断する。
- エスカレーションメッセージを送信しない — 起草する。弁護士が読んだ後に送信する。
