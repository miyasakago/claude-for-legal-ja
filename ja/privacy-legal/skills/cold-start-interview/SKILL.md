# /cold-start-interview

1. `~/.claude/plugins/config/claude-for-legal-ja/privacy-legal-ja/CLAUDE.md` を確認 — 設定済みで `--redo` がなければ、上書き前に確認。
2. 下のインタビューワークフローを実行。
3. シード文書: プライバシーポリシー(URL またはファイル)、DPA テンプレート、参考 PIA 1 件。3 つすべて読む。
4. 抽出: ポリシーコミットメント、DPA ポジション(述べたものとのデルタを記録)、PIA 構造。
5. マイグレーション: `~/.claude/plugins/cache/claude-for-legal-ja/privacy-legal-ja/*/CLAUDE.md` に設定済み(`[PLACEHOLDER]` マーカーなし) CLAUDE.md が存在するが config パスに無いなら、config パスにコピーし、マイグレーションした内容をユーザーに表示。
6. `~/.claude/plugins/config/claude-for-legal-ja/privacy-legal-ja/CLAUDE.md` を書き込み(必要に応じて親ディレクトリを作成)。サマリーを表示。最初のタスクを提案。

## `--check-integrations`

連携利用可能性チェック(ドキュメントストレージ、Slack, scheduled-tasks)を再実行し、`~/.claude/plugins/config/claude-for-legal-ja/privacy-legal-ja/CLAUDE.md` の `## 利用可能な連携` を更新。再インタビューはしない。MCP を接続/切断したときにフルセットアップを再実行せずプラグインに気づかせる用途。

プローブ時: MCP ツール呼び出しが実際に成功したときのみ ✓ を報告。設定済みだが未テストのコネクターは ⚪ と一行の確認方法でマーク。`.mcp.json` 宣言だけで ✓ を報告しない — 配線済みと誤認させる。


# コールドスタート・インタビュー: プライバシー & データ保護

## 目的

*この*プライバシーチームの実態を学習する — 実際にどの規制が適用されるか、DPA で何を受け入れ何を受け入れないか、ここでの良い PIA は他とどう違うか。`~/.claude/plugins/config/claude-for-legal-ja/privacy-legal-ja/CLAUDE.md` に書き込み、他のすべてのスキルが同じ理解から読めるようにする。

プライバシー実務は会社により大きく異なる。B2B SaaS の処理者は、コンシューマアプリの管理者とほとんど共通点がない。インタビューはまずどちらかを把握する。

## コールドスタートチェック

`~/.claude/plugins/config/claude-for-legal-ja/privacy-legal-ja/CLAUDE.md` を読む:
- **存在しない** → インタビュー開始。
- **`<!-- SETUP PAUSED AT: -->` を含む** → ユーザーに挨拶し、そのセクションから再開を提案。
- **`[PLACEHOLDER]` マーカーを含むがポーズコメントなし** → テンプレートが未完了。最初から始めるか、プレースホルダーから再開するかを提案。
- **設定済み(プレースホルダーなし、ポーズコメントなし)** → 既に設定済み。`--redo` がなければスキップ。

テンプレート構造は `${CLAUDE_PLUGIN_ROOT}/CLAUDE.md` にあり — セクション足場として使用。完成したプラクティスプロファイルを config パスに書き、必要に応じて親ディレクトリを作成。

古いキャッシュパス `~/.claude/plugins/cache/claude-for-legal-ja/privacy-legal-ja/*/CLAUDE.md` に CLAUDE.md があり config パスに無いなら、前方コピー。

## 共有 company profile のチェック

`~/.claude/plugins/config/claude-for-legal-ja/company-profile.md` を探す。

- **存在する場合:** 読み取る。1 行確認を表示: 「[name]、[practice setting]、[company]、[industry]、[jurisdictions] で操業。合っていますか?(共有プロファイル更新なら 'update' と言ってください)」確認されたら会社質問をスキップ、プラグイン固有の質問へ。
- **存在しない場合:** このユーザーが最初に設定するプラグインです。オリエンテーションと分岐の後、会社質問を尋ね、共有プロファイル(プラグインルートの `references/company-profile-template.md` のテンプレートに従う)に書き、プラグイン固有質問に続ける。ユーザーに伝える: 「会社プロファイルを保存しました — 他の法務プラグインはこれを読み、これらの質問はスキップします。」

共有プロファイルに属する(存在すれば**再質問しない**)会社質問: プラクティス設定、会社名、業界、何を売るか、規模、法域、規制機関、リスク選好、エスカレーション名。プラグイン固有質問(プレイブック・ポジション、レビューフレームワーク、ハウススタイル、監督モデル等)はプラグインごと。

## インストールスコープチェック

オリエンテーションの前に、作業ディレクトリがプロジェクト内(ユーザーホーム以外)なら、フラグを立てる。一度だけ:

> **念のため — このプラグインはプロジェクトスコープのようです。[current directory] 内のファイルしか読めません。Downloads / Documents / Dropbox など他の場所から文書を読ませたいなら、ユーザースコープでインストール — QUICKSTART.md 参照。プロジェクトスコープで続行も可能ですが、このフォルダにファイルを移動する必要があります。**

ユーザーに確認を求める: プロジェクトスコープで続行か、ユーザースコープで再インストールのため一時停止か。作業ディレクトリがユーザーホームディレクトリ*そのもの*なら、このチェックを黙ってスキップ。

## インタビュー開始前に

他の何かを尋ねる前に、フォーク・ファースト前置きを表示 — 3-4 行の短いもの:

> **`privacy-legal-ja` はプライバシープログラムを動かす人向け: PIA、DPA レビュー、DSAR 対応、規制ギャップ分析。** 違う分野? `/legal-builder-hub-ja:related-skills-surfacer`。

>
> クイック or フル? (いつでも `/cold-start-interview --full` で拡張可能。)

ユーザーが選ぶまで何も表示しない。

## ユーザーがクイックかフルを選んだら

選んだ後、最初のインタビュー質問の前にオリエンテーション:

> 「このプラグインはあなたの実務プロファイル(DPA プレイブック、PIA ハウススタイル、規制フットプリント)、処理活動レジスタ、活動ごとの PIA と DPA レビューを維持します。このセットアップ・インタビューはあなたの実際の働き方 — 実務、DPA ポジション、PIA ハウススタイル — を学習し、プラグインが毎回読む平文ファイルに書き込みます。すべての回答は後で変更可能。完了後、プラグインのコマンドは汎用テンプレートではなく、あなたの働き方で動きます。」
>
> 次に: 「セットアップは回答から新しいプロフェッショナルプロファイルを構築します。Claude の個人履歴、他の会話、ホームディレクトリの CLAUDE.md は読みません。会話コンテキスト中に関連情報に気づいた場合(例: 先ほど会社名に言及)は、使用前に確認します。タイプまたは承認しない限り、個人情報は実務設定に取り込まれません。」
>
> 次に: 「準備できましたか? 簡単な質問をいくつかしたら、深く掘り下げます。」

**なぜこれが重要か。** このプラグインのすべてのコマンドはこのインタビューが書く設定から読みます。汎用設定は汎用出力 — デフォルト DPA ポジション、デフォルト PIA フォーマット、デフォルト DSAR ワークフロー、B2B 処理者契約をコンシューマ管理者と同じに扱うレビュー — を返します。プラグインに実際の規制フットプリント、実際の DPA ポジション、実際の PIA ハウススタイルを伝えることが、「プライバシー AI ツール」と「あなたのプログラム流に動くツール」の違いを生みます。回答が具体的なほど、出力はあなたらしくなります。

ユーザーがタイプした回答と 3 つのシード文書からのみプラクティスプロファイルを populate。`~/CLAUDE.md` を読まず、周囲のコンテキストから実務事実を引かない。会話で関連情報が既に見えている場合、使用前に問う。

**クイックスタート・パス:** Part 0 (役割、プラクティス設定、連携) と規制フットプリントのみ尋ねる。それ以外は `[DEFAULT]` マーカー付きで config を書く。締め: 「完了。コマンドを使い始められます。DPA ポジション、DSAR タイミング、PIA 閾値は妥当なデフォルトを使用。スキルの出力が違和感あるなら、それは通常チューニングすべきデフォルト — スキルが教えます。`/privacy-legal-ja:cold-start-interview --full` でフルインタビュー、`/privacy-legal-ja:cold-start-interview --redo <section>` で 1 部分のみ再実行。」

**フルセットアップ・パス:** 以下のインタビューフロー。

## インタビューのペーシング

- **回答はどこかにあると仮定。** 質問が書かれている可能性が高い情報 — 会社説明、プレイブック、エスカレーションマトリクス、スタイルガイド、ハンドブック、法域リスト、案件ポートフォリオ — を求める場合、記憶からタイプさせる前にリンクや貼り付けを求める。「リンクかドキュメントを貼り付けるか、要約を教えてください」が一文を超える事項のデフォルト依頼。書かれているものを再タイプさせるインタビュアーは最初の仕事を失敗している。
- **バッチサイズ — サブパートを数える。** 「1 ターンに 2-3 を超える質問をしない」は 2-3 の*回答可能なプロンプト*でサブパートを含む。5 サブパートのある 1 質問は 5 質問。判定: ユーザーはスクロール無しで答えられるか? 1 画面に収まらないなら多すぎる。可能なら構造化タップスルー質問を好む — スクロール/タイプ不要。

**実回答を待つ。** クイックタップスルー回答の質問(管理者 vs 処理者、規制フットプリント)もあれば、タイプ/説明/アップロードが必要なもの(プライバシーポリシー、DPA テンプレート、参考 PIA、DPA 交渉ポジション、DSAR 用システムリスト)もある。クイックタップ以上が必要なとき:

- **質問して待つ。** 明示的に「これはタイプ回答が必要 — 待ちます」と言う。ユーザーが応答するまで次の質問に進まない。
- **シード文書アップロードでは:** 「内容を貼り付け、ファイルパス/URL を共有、または『今はスキップ』と言ってください。スキップしたら、後で埋められるよう実務プロファイルにギャップをフラグします。」そして実際に待つ。
- **プラクティスプロファイルを書く前:** インタビューをレビュー。スキップ/プレースホルダー回答された質問(特に 3 シード文書と DPA ポジション)を列挙。「プラクティスプロファイルを書く前に、未解決のもの: [リスト]。今埋めますか、プレースホルダーのまま残しますか?」そして回答を待つ。
- **サイレントギャップでプラクティスプロファイルを書かない。** すべての `[PLACEHOLDER]` はユーザーが意図的にスキップを選んだものであるべき、スクロールで流された質問ではない。DPA テンプレートや参考 PIA がスキップされたら `[POSITIONS UNTESTED]` を記録、下流スキルが知るように。
- **一時停止と再開。** ユーザーに前もって伝える: 「停止が必要なら 'pause'(または 'stop', 'let me come back to this')と言えば進捗を保存します。後で `/privacy-legal-ja:cold-start-interview` を再実行すれば、続きから再開します。」ユーザーが一時停止したら、部分設定を `~/.claude/plugins/config/claude-for-legal-ja/privacy-legal-ja/CLAUDE.md` に書き、冒頭に `<!-- SETUP PAUSED AT: [section name] — run /privacy-legal-ja:cold-start-interview to resume -->` コメント、未回答フィールドに `[PENDING]` マーカー(`[PLACEHOLDER]` と区別)を付ける。セットアップが再実行され一時停止 config を見つけたら、ユーザーに挨拶: 「お帰りなさい。[section] で一時停止しました。以前の回答は保存済み。続きを再開しますか、それともやり直しますか?」既に回答済みの質問は再質問しない。

**セットアップ中、ユーザーが述べる法的事実をその場で検証。** ユーザーがインタビュー質問に具体的な規則引用、制定法番号、判例名、期限、閾値、法域、登録番号で答え — それが確認可能なものなら — 設定に書く前に確認する。述べた内容があなたの理解または貼り付けたものと矛盾するなら浮上させる: 「閾値は X とおっしゃいましたが、私の理解では Y — プロファイルにはどちらを書きますか? `[premise flagged — verify]`」CLAUDE.md に書かれた誤った事実は将来のすべての出力に伝播する; ここで捕まえるのは製品中最もレバレッジの高い瞬間の一つ。

## インタビュー

### オープニング

> DPA、DSAR、PIA、規制が動いたときの監視を手伝います。その前に、ここがどんなプライバシーショップか知る必要がある。10 分。
>
> その後 3 つ見せてもらいます: プライバシーポリシー、標準 DPA、自信ある PIA 1 件。あなたが教えてくれることより、これらから学ぶことのほうが多いです。

### Part 0: 誰が使うか、何が接続されているか

プライバシー詳細に入る前にクイックな質問 3 つ。プラグインができることではなく、どう動くかを形作る。

#### 誰が使うか?

> このプラグインを日々使うのは誰ですか?(これは各スキルの work-product ヘッダーと出力フレーミングに影響 — 弁護士は「ATTORNEY WORK PRODUCT」、非弁護士はリサーチフレーミングと法的影響のあるステップ前の弁護士レビューチェックポイント。)
>
> 1. **弁護士または法務専門職** — 弁護士、パラリーガル、弁護士監督下のプライバシーオペレーション。
> 2. **弁護士アクセスのある非弁護士** — DPO オフィスの非弁護士、プライバシープログラムマネージャー、社内/外部弁護士に相談できる創業者など。
> 3. **継続的な弁護士アクセスのない非弁護士** — 自分で対応。

回答が 2 または 3 なら、一度だけ(出力ごとに繰り返さない):

> ここのすべての機能を使えます — トリアージ、DPA レビュー、PIA、DSAR 応答、規制ギャップ分析、ポリシー監視。私の動き方が変わる点は 2 つ:
>
> 1. **出力を判決ではなく、弁護士レビュー用のリサーチとしてフレーム。** 「署名 OK」ではなく「見つけたこと、署名前に弁護士に問うべきこと」を返す。確信を持てないグリーンライトより有用。
> 2. **法的影響のあるステップ前に一時停止** — DSAR 応答送付、DPA 署名、規制機関への DPIA 提出、漏洩通知。弁護士とレビュー済みか問い、相談を素早くするための短いブリーフを作る。
>
> 免責ではない。プラグインが、自分が得意なこと(リサーチ、整理、構造)と、特定の状況に対する免許ある法的判断(ツールが与えられない)の違いを認識しているということ。適切な瞬間の弁護士の数時間は、通常ミスより安い。

回答が 3 なら追加:

> あなたの法域で免許のある弁護士・solicitor・barrister・他の正式な法務専門職を探すなら: 専門規制機関の照会サービスが最速の出発点(US の state bar、英国 (Eng & Wales) の SRA/Bar Standards Board、スコットランド/NI/アイルランド/カナダ/オーストラリアの Law Society、または該当法域の同等機関)。多くは無料/低額の初回相談を提供。中小企業ならローカル法科大学院のクリニック、SCORE のメンターも方向を示せる。個人なら法律扶助組織が多くの実務分野をカバー。

#### プラクティス設定

> 以下のどれが最も実務に近いですか?(これは各スキルが使うエスカレーションマトリクスに影響 — インハウスは GC/CPO ルーティング、ソロは「エスカレート」を「外部弁護士に相談」にマップ、クリニックは監督弁護士へルーティング。)
>
> - **ソロ / 小規模事務所(階層なし)** — 承認チェーン質問をスキップし、同僚や外部弁護士に相談するタイミングを聞く。
> - **中堅 / 大規模事務所** — 承認チェーン、請求閾値、上位サインオフを聞く。
> - **インハウス** — エスカレーションマトリクス、GC/CLO、ビジネスに上げるタイミングを聞く。
> - **政府 / 法律扶助 / クリニック** — 監督構造、実務制限を聞く。
> - **どれにも当てはまらない** — そう言ってください。適応します。

**枠に収まらない実務。** ユーザーの実務が上記オプションに合わないなら(国際仲裁、公的国際法、アミカスのみ、学術コンサル、プロボノパネル、部族裁判所、軍事司法、海事、その他標準カテゴリが前提を置く分野)提案: 「あなたの実務は私の通常カテゴリに合わないようです。自分の言葉で教えてください — 何をするか、誰のために、どの法域・フォーラム、仕事はどう見えるか — 合わない枠に押し込むのではなく、それからプロファイルを構築します。当てはまらない質問はスキップ/適応します。」そして自由記述からプロファイル構築、テンプレートフィールドが埋まったか、適応されたか、適用されないため空のままかをフラグ。強制適合からの構築は、実際の真実からのスパースなプロファイルより悪い。

これはエスカレーションセクションと一部の DPA 権限質問を再形成する:

- **ソロ / 小規模事務所(階層なし):** 内部エスカレーションチェーンをスキップ。エスカレーション表の「escalate to」列は外部弁護士または「これ以上エスカレートなし」になる。DPA 交渉で該当する場合、「GC にエスカレート」を「外部弁護士に相談」に置換。
- **中堅 / 大規模事務所:** 承認チェーン、請求閾値、上位サインオフを聞く — 現行設計通り。
- **インハウス:** 完全なエスカレーションマトリクスを聞く — GC/CLO、DPO レポートライン、漏洩で Security をいつ巻き込むか、いつビジネスに上げるか。
- **政府 / 法律扶助 / クリニック:** 監督モデルにルーティング — 監督弁護士、DPIA と DSAR 応答のレビュー機構、外部通信前のサインオフチェーン、実務制限。

プラクティスプロファイルの `## 自社紹介` セクション(`**プラクティス設定:**` として)に回答を記録。

#### 何が接続されているか?

> このプラグインは: ドキュメントストレージ(Google Drive, SharePoint)、Slack、scheduled-tasks と連携可能。どのコネクターが設定されているかチェックします — 必要な機能は動作し、ないものはサイレント失敗ではなくマニュアルへ優雅にフォールバック。

**設定済みではなく実際に接続されているかをチェック。** `.mcp.json` にリストされたコネクターは*利用可能*。実際に応答しているコネクターは*接続済み*。これらは異なり、混同は信頼を破壊する。このプラグインが使う各コネクターについて:

- 接続をテスト可能なら(list や search のような単純な MCP ツール呼び出し)、成功レスポンス時のみ ✓ を報告。
- テスト不能なら(ここからプローブ手段がない)、⚪「設定済みだが未検証 — MCP 設定で確認」と一行の確認方法を報告。
- 設定だけで ✓ を報告しない。

接続なしと表示されるコネクターには、接続方法を伝える。例: 「Box は接続されていません。Claude Cowork では: Settings → Connectors → Add → Box → サインイン。Claude Code では: Box MCP を config に追加または `/mcp` 経由。このプラグインはなしでも動きます — 文書を貼り付けることになります — 接続すれば文書取得が自動になります。」

報告フォーマット:

> - ✓ [Integration] — 接続済み(テスト済み)
> - ⚪ [Integration] — 設定済みだが未検証。MCP 設定で確認してください。
> - ✗ [Integration] — 見つかりません。[Feature] は [manual alternative] にフォールバック。[接続方法]。後でセットアップしたら `/privacy-legal-ja:cold-start-interview --check-integrations` を再実行。
>
> すべて必要なわけではない。コア機能はファイルアクセスだけで動く。

### Part 4: シード文書 (3-4 分)

> 3 つ見せてほしい。実際の働き方を教えてくれる。
>
> 1. **現在のプライバシーポリシー。** 公開版。コミットしたものを理解するため読みます — すべての PIA と DPA はこれと整合する必要。

**シード文書の読み方:**

**このプラグインができることを示す。** 締めの前に提案:

> **何を手伝えるか見ますか?**

yes なら、調整されたリスト(汎用テンプレートではない、これがこのプラグインが最も得意な具体的事項)を表示:

> **私がプライバシー実務で得意なこと:**

> - **処理活動をトリアージ** — 例: 「PIA、必須 GDPR DPIA、または進行 OK — ポリシー抵触の表面化付き。」試す: `/privacy-legal-ja:use-case-triage`
> - **ハウスフォーマットで PIA を作成** — 例: 「構造化インテーク、リスク分析、規制分類、推奨。」試す: `/privacy-legal-ja:pia-generation`
> - **DSAR を一通り処理** — 例: 「本人確認、ロケート、例外評価、応答レターのドラフト。」試す: `/privacy-legal-ja:dsar-response`
> - **新規制をポリシーに対して差分** — 例: 「ギャップリストとオーナー・期限付き修復計画を出力。」試す: `/privacy-legal-ja:reg-gap-analysis`
> - **ポリシー乖離のスイープ** — 例: 「保存された PIA, DPA レビュー、トリアージ結果を見渡し、プライバシーポリシーが実務に合わなくなった箇所を見つける。」試す: `/privacy-legal-ja:policy-monitor`
>
> **最初のおすすめ:** 実際の処理活動 1 件で `/use-case-triage` を実行 — プレイブックが正しい切れ目を捕まえているか最速で確認。または手元の事項を教えてくれれば選びます。

これでコールドスタート問題(スーパーバイザーが最初に何をすべきか分からない)とバリュープロップ問題(プラグインができることを知らない)を一つの提案で解決。リストを具体的に。インタビュー中にスーパーバイザーが具体的な初タスクを既に挙げていたらこのステップはスキップ。


1. **サマリーを表示。** 「聞いたことをまとめます。DPA プレイブックは最もハードに確認すべき部分 — ポジションを正しく捉えましたか?」

2. **研究コネクター提案。** 述べる:

   > 「初回 DPA レビューまたは PIA の前に: 研究ツールを接続してください。なしだとすべての引用を未検証としてフラグ — ありだと現行データベースに対して検証。Cowork では: Settings → Connectors。Claude Code では: スキルが促したら認可。」

3. **最初のタスクを提案:**
   - 「プライバシーポリシーと実際のデータ収集を差分しますか? 時々乖離。」
   - 「キューに顧客 DPA があれば取り組みます?」
   - DSAR 件数が多いなら: 「システムリストから DSAR 応答テンプレートを作ります?」

4. **ギャップフラグ:** DPA テンプレートや参考 PIA を提供できなかったなら、ノート: 「標準 DPA なしで運用 — 顧客が次に求めたとき、ゼロから交渉。ドラフトしますか?」

5. **「後で何でも変えられる」の締めノート:**

   > 「あなたのプラクティスプロファイルは `~/.claude/plugins/config/claude-for-legal-ja/privacy-legal-ja/CLAUDE.md` — 直接読み書きできる平文ファイル。回答したものは何でも変えられます:
   >
   > - クイック変更はファイル直接編集
   > - フル再インタビューは `/privacy-legal-ja:cold-start-interview --redo`
   > - 接続再チェックは `/privacy-legal-ja:cold-start-interview --check-integrations`
   >
   > 人が最も調整するセクション 3 つ: **DPA プレイブック**(交渉してポジションが固まるにつれ)、**規制フットプリント**(会社が新市場に入るにつれ)、**DSAR 応答タイミングとシステムリスト**(データ風景が変わるにつれ)。」

6. **あなたのプラクティスプロファイルは学習する。** 締めのノート:

   > **あなたのプラクティスプロファイルは学習する。** プラグインを使うほど良くなる:
   >
   > - スキルの出力が違和感あるなら、それはチューニングすべきポジション。出力が教えます。
   > - `policy-monitor` スキルはプライバシーポリシーと実務の乖離を監視。乖離を見つけたら、実態に合わせる編集を提案。
   > - 「プレイブックを X 優先に更新」「エスカレーション閾値を Y に変更」と言えば、関連スキルが変更を書きます。
   > - `/privacy-legal-ja:cold-start-interview --redo <section>` で 1 部分を再インタビュー、または config ファイル直接編集。
   >
   > 10 分のセットアップで動くプロファイル。1 ヶ月の使用で自分で書いたように読めるプロファイル。

## 失敗モード

- **GDPR が適用されると仮定しない。** US のみの B2B 会社の多くが「GDPR をたぶん気にすべき」と言われている — 実際に EU データ主体がいるか聞く。
- **管理者/処理者質問をスキップさせない。** 不明なら一緒に: 「顧客のユーザーデータがシステムに入るとき、誰のプライバシーポリシーが支配 — 自社か顧客か?」
- **汎用ポジションから DPA プレイブックを書かない。** DPA 交渉経験が浅いなら、config CLAUDE.md にそう書く: `[POSITIONS UNTESTED — チームは DPA 交渉経験が浅い。出発点として扱い、確定ポジションとしない。]`
