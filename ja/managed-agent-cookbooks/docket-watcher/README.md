# Docket Watcher — Managed Agent テンプレート

## 概要

アクティブな訴訟ポートフォリオの案件について、裁判所のドケットを監視します。Trellis は州の trial court をカバーし、CourtListener / PACER は連邦裁判所をカバーします。各アクティブ案件について、エージェントは前回チェック以降の新規提出書面をプルし、提出書面の種別を候補となる期限にマッピングし、案件履歴とオープンな成果物に照らしてクロスリファレンスを行い、ドケット状況レポートと構造化された期限フィードを生成します。

litigation-legal Claude Code プラグインの [`docket-watcher`](../../litigation-legal/agents/docket-watcher.md) エージェントと同一ソース ― このディレクトリは `POST /v1/agents` 向けの Managed Agent クックブックです。

## ⚠️ デプロイ前に

- **計算された期限はリードであって、カレンダーエントリーではありません。** 裁判所の期限ルールは法域、裁判所、裁判官、ローカルルールによって異なり、standing order(常設命令)や事件固有の case management order(訴訟管理命令)で変更されることがあります。裁判所の期限を見逃すと、医療過誤(malpractice)に相当する結果につながります。資格を有する弁護士が、ドケットに登録される前に、計算された期限を裁判所の実際のルールおよび事件固有の命令と照らして検証します。エージェントはこの判断の上流にあるのであって、その代替ではありません。
- **提出書面の分類はヒューリスティクスです。** エージェントが誤分類した提出書面 ― 行政的な motion を dispositive motion と読む、stipulation を discovery dispute と読む ― は、誤った期限ルールを生成しかねません。書面を読んでください。ラベルを信頼しないでください。
- **未知の裁判所はデフォルトではありません。** 法域別ルールテーブルが該当裁判所をカバーしない場合、マッパーは `confidence: low` + `needs_verification: true` を生成しなければならず、サイレントなデフォルトを生成してはいけません。マイナーな裁判所で自信を持った期限を見たら、ルールテーブルが古いと仮定するまで信用しないでください。
- **静かなドケットは綺麗なドケットではありません。** クラークの記載は遅れます。Minute entry はイベントから数日後に到着することがあります。「新規提出書面なし」はフィードに関する記述であり、事件に関する記述ではありません。

## セキュリティとハンドオフ

裁判所への提出書面は公的記録ですが、信頼できない入力(UNTRUSTED INPUT)でもあります。提出者がテキストを制御し、エージェントを狙ったプロンプト、URL、指示を埋め込めます。3 層の分離:

| ティア | 提出書面に触れる? | ツール | コネクタ |
|---|---|---|---|
| **`docket-reader`** | **Yes** | `Read`, `Grep` のみ | trellis、courtlistener(読み取り専用) |
| `deadline-mapper` / Orchestrator | No — 構造化 JSON のみを見る | `Read`, `Grep`, `Glob`, `Agent` | gdrive(法域設定、読み取り専用) |
| **`tracker-writer`**(Write 保有者) | No | `Read`, `Write`, `Edit` | なし |

`docket-reader` は長さ制限・スキーマ検証済みの JSON を返します。`deadline-mapper` は MCP も Web も持たず、デプロイチームが設定したルールを適用します。`tracker-writer` は `./out/docket-report-<date>.md` と `./out/deadlines.yaml` を生成し、生提出書面は一切見ません。

## 適応ノート

このクックブックは出発点です。以下を行うまでは本番で動作しません。

- **MCP URL を設定する。** `TRELLIS_MCP_URL` と `COURTLISTENER_MCP_URL` は、お客様のデプロイのエンドポイントを指し、プラットフォームが要求する認証を備える必要があります。`GDRIVE_MCP_URL`(または代替)は、法域ルールテーブルの所在を指します。
- **ポートフォリオを読み込む。** エージェントは `matters/_log.yaml` と、デプロイチームの litigation-legal 設定からの案件ごとの `docket_id`、`court` を読み込みます。お客様のドケッティングシステムが信頼できる情報源である場合、MCP か、設定パスへのスケジュールド同期でフロントしてください。
- **法域ルールを設定する。** ポートフォリオ内のすべての裁判所について、ローカルルールテーブルを deadline-mapper に同梱してください。連邦ルールは一度エンコードすればよいですが、州の trial court と個別の裁判官は地雷原です。未知の裁判所は `confidence: low` + `needs_verification: true` を生成しなければならず、サイレントなデフォルトを生成してはなりません。
- **配信を結線する。** 出力先を決めます: ドケッティングシステムが `./out/deadlines.yaml` を取り込み、ナラティブレポートは Slack、メール、または案件管理ワークスペースへ送り、致命的なフラグは起こすべき相手に届きます。
- **スケジュールを設定する。** ほとんどの案件は週次。14 日以内に hearing がある案件、`trial` または後期 `discovery` ポスチャの案件、`risk: critical` の案件は日次。

## 計算された期限はリードであって、カレンダーエントリーではありません

**このエージェントが生成する計算済み期限は、ドケットに登録される前に、支配的なローカルルール、standing order、case management order に照らして人間が検証する必要があります。裁判所の期限を見逃すと医療過誤に相当する結果につながります。このエージェントは期限を浮かび上がらせ、人間が検証してドケットします。**

すべての期限は `confidence` と `needs_verification` フィールドを持ちます。レポートは低信頼度のエントリーを分離し、明確な連邦ルールから導出されていないものには検証コールアウトをスタンプします。これを人間レビューの最小値として扱ってください ― 上限ではありません。裁判官は個別命令でデフォルトを上書きし、ローカルルールは変わり、クラークが実際に送達を記録した日はドケットに表示される日と異なるかもしれません。

**保証されないこと:** このエージェントは期限を推奨します。ドケッティング担当の弁護士が支配的ルールに照らして確認し、日付を予定登録します。
