# Launch Radar — Managed Agent テンプレート

## 概要

プロダクトチームのローンチトラッカー(Jira、Linear、Asana)を、今後数週間で法務レビューを要するであろうローンチについてスケジュールド・スキャンします。各ローンチをプロダクトカウンセルのリスクキャリブレーションに照らしてトリアージし、週次レーダーメモを生成します: 何が来るか、何が法務の注意を要するか、何がフラグを引いたか。litigation-legal Claude Code プラグインの [`launch-watcher`](../../product-legal/agents/launch-watcher.md) エージェントと同一ソース ― このディレクトリは `POST /v1/agents` 向けの Managed Agent クックブックです。

これは**クックブックであって製品ではありません。** そのままでは動きません。MCP コネクタをお客様のトラッカーに向け、リスクキャリブレーションを読み込み、頻度を設定し、メモの配信先を設定する必要があります。下記の適応ノートを参照してください。

## ⚠️ デプロイ前に

- **レーダーのトリアージはルーティング判断であって、法務レビューではありません。** 「Needs review」はプロダクトカウンセルが見るべきという意味であり、「FYI」はローンチが大丈夫という意味ではなく、「skip」はローンチをクリアにする意味ではありません。フラグされた項目だけでなくレーダー全体をレビューしてください ― フラグされなかった項目こそ、見落としてはならない案件が紛れ込む場所です。
- **リスク分類はプラグイン設定のキャリブレーションを使います。** キャリブレーションが古ければ、トリアージも古いです。新しいプロダクトライン、新しい規制当局、新しい地域、新しいサードパーティ依存は、レーダーがそれらをルーティングできるようになる前に、キャリブレーションに反映される必要があります。
- **トリガーキーワードリストは意見を持ちます。** お客様のプロダクト面がデフォルトに合わない場合(例: バイオメトリクス偏重、FedRAMP 対応必須、デフォルトキーワードでカバーされない方法で未成年者データを取り扱う)、初回実行前にチューニングしないとメモは捕捉すべき案件を取りこぼします。
- **トラッカーチケットは信頼できない入力です。** PM はタイトルや説明に何でも書けますし、攻撃者がチケットを作成することもできます。トリアージはコンテンツでルーティングしますが、チケットを保証するわけではありません。

## デプロイ

```bash
export ANTHROPIC_API_KEY=sk-ant-...
export LINEAR_MCP_URL=... ATLASSIAN_MCP_URL=... ASANA_MCP_URL=... GDRIVE_MCP_URL=...
../../scripts/deploy-managed-agent.sh launch-radar
```

実際に使用するトラッカーの MCP URL のみを設定してください。Orchestrator と `tracker-reader` は設定されていない MCP をスキップします。

## ステアリングイベント

[`steering-examples.json`](./steering-examples.json) を参照してください。典型的な頻度は 4〜6 週間の地平線での週次スキャンに加え、PM がプロダクトカウンセルに「これは問題?」とピングしてきた場合のオンデマンドの単一チケットトリアージ。

## セキュリティとハンドオフ

トラッカーチケットは信頼できない入力です。プロダクトマネージャはタイトル、説明、コメントに任意のテキストを入れられますし、攻撃者がチケットを作成することもできます。3 層の分離:

| ティア | 信頼できないトラッカーコンテンツに触れる? | ツール | コネクタ |
|---|---|---|---|
| **`tracker-reader`** | **Yes** | `Read`, `Grep` のみ | Linear、Jira(atlassian)、Asana(読み取り専用) |
| `risk-classifier` / Orchestrator | No | `Read`, `Grep`, `Glob`, `Agent` | Orchestrator のみ: Linear / Jira / Asana / Drive(読み取り専用) |
| **`memo-writer`**(Write 保有者) | No | `Read`, `Write`, `Edit` | なし |

`tracker-reader` は長さ制限・スキーマ検証済みの JSON ローンチリストを返します。`risk-classifier` は MCP もネットワークも持たず、検証済みリストとユーザーのキャリブレーションファイルから動作します。`memo-writer` は Write を持つ唯一のワーカーで、`./out/launch-radar-<date>.md` を生成します。Orchestrator は Write を持たず、生のチケット本体を自分でパースしません。

**ハンドオフ:** ローンチがレーダーエントリーではなく完全な法務レビューメモを要する場合、Orchestrator はインラインでメモを起こすのではなく、`launch-review` スキル(新しいセッションで動作)に対する `handoff_request` を発出します。`scripts/orchestrate.py` がそれをルーティングします。

## 適応ノート

これが有用になる前に変更すべき項目:

- **トラッカーポインタ。** [`agent.yaml`](./agent.yaml) と [`subagents/tracker-reader.yaml`](./subagents/tracker-reader.yaml) の `mcp_servers` を、お客様のトラッカーの MCP URL に編集してください。Jira/Linear/Asana のうち 1 つしか使わない場合は他の 2 つをドロップしてください。お客様のトラッカーがリストになければ、実際に使う MCP を入れ替え、`tracker-reader` の system prompt をそれに合わせて更新してください。
- **リスクキャリブレーション。** `risk-classifier` はユーザーのキャリブレーションを `../../product-legal/CLAUDE.md`(`/product-legal-ja:cold-start-interview` で populate されます)から読みます。コールドスタートを実行していない場合、それを先に行うか、初回スキャン前に「Usually blocks / Usually requires work / Usually FYI」テーブルを持つ CLAUDE.md を手で書いてください。キャリブレーションがなければ、classifier はキーワードトリガーのみにフォールバックし、ノイジーになります。
- **スキャン頻度と地平線。** デフォルトは週次 / 6 週間。お客様のローンチ頻度に応じて、日次や隔週が適切な場合があります。リードタイムが短いと地平線を長くする必要があります。頻度はエージェント内ではなく、お客様のスケジューラ(cron、Temporal、Airflow、EventBridge)で設定してください。地平線はステアリングイベントで渡されます。
- **配信チャンネル。** デフォルトでメモは `./out/` に出力されます。代わりに(または追加で)Slack に投稿するには、(a) Slack MCP をクックブックに追加し、書き込み後に投稿するよう `memo-writer` を更新するか、(b) お客様のオーケストレーション層に `./out/launch-radar-<date>.md` をピックアップさせて転送させる、のいずれかです。このパターンは配信をエージェントから切り離しテストしやすくします ― お客様の運用ストーリーに合う方を選んでください。
- **トリガーキーワード。** `launch-watcher` の system prompt にあるキーワードリストは意見を持ちます(COPPA、HIPAA、AI ベンダー名など)。当てはまらないカテゴリは削除し、ドメイン固有用語(FedRAMP、PCI、HITRUST、TCPA、バイオメトリクス等)を追加し、キャリブレーションテーブルに対して severity 閾値を調整してください。変更後にデプロイし直してください。
- **特権ヘッダー。** `memo-writer` はプラグイン設定からの成果物ヘッダーを先頭付加します。デプロイ前に GC で正確なマーキングを確認してください ― 法域ごとのバリエーションが適用されます。

## 得られるもの、得られないもの

- **得られるもの:** 動作するマニフェスト、セキュリティ階層化されたパイプライン、各ローンチをそのトラッカー URL に引用するメモ、完全な launch-review スキルへのハンドオフパス。
- **得られないもの:** 本番運用可能なエージェント。お客様のトラッカーに向け、キャリブレーションを読み込み、頻度を設定し、評価を実行し、プロダクトカウンセルが信頼する前に同じチケットに対する自身の読みと最初の数件の出力を比較してください。
- **特に得られないもの:** プロダクトカウンセルの代替。このエージェントはトリアージします。レビュー・フラグ・判断は弁護士の役割です。メモ内の「needs review」項目はリードであって、判決ではありません。
