# inbound/ — 受領した法務関連通信

このフォルダは、外部から到着するあらゆるものに対するトリアージと対応のワークを保持します: 受領した要求書、会社に送達されたサブポエナ(召喚状)、規制当局の照会、保全要求、自社宛の警告状(Cease & Desist)など。

`demand-letters/`(送信側)や `matters/`(トラッキング対象のポートフォリオ)と分けている理由は、インバウンド項目に独自のワークフローがあるからです: 読む → トリアージ → 決定 → 対応(または案件化へエスカレーション)。すべての受領物が案件化されるわけではありません。

## レイアウト

```
inbound/
├── _README.md
└── [slug]/
    ├── incoming.pdf              # または .eml / .docx — オリジナル(またはリンク/ポインタ)
    ├── triage.md                 # 分析: スコープ、メリット、選択肢、推奨
    └── response-v1.docx          # 起案した回答(対応する場合)(イテレーションに応じて v2, v3)
```

## Slug の規約

`[type]-[sender-short]-[yyyy-mm]`。例:

- `demand-rec-acme-2026-04`(受領した要求書)
- `subpoena-smith-v-us-2026-04`(第三者サブポエナ)
- `regulator-ftc-inquiry-2026-04`
- `preservation-vendor-2026-04`(受領した保全レター)

## ワークフロー

| タイプ | コマンド | 出力 |
|---|---|---|
| 要求書を受領 | `/litigation-legal-ja:demand-received [path]` | triage.md + 任意で回答ドラフト |
| サブポエナ送達 | `/litigation-legal-ja:subpoena-triage [path]` | triage.md + 異議メモ |
| 規制当局の照会 | *将来のスキル* | |

各トリアージは、関連案件(同一相手方、対象事項の重複)について `matters/_log.yaml` をクロスチェックします。関連案件が存在する場合、トリアージはそれをフラグし、`related_matter` エントリとして追加することを提案します。このインバウンド項目自体が案件化すべき場合、トリアージはフィールドを事前入力した状態で `/matter-intake` にハンドオフします。

## 案件との関係

- インバウンド + 既存案件と関連 → `_log.yaml` の `related_matters` フィールドでリンク; ファイルは `inbound/` に残る。
- インバウンド + 案件化すべき → 案件を作成; matter.md が `inbound/[slug]/` へクロスリンク。
- インバウンド + 対応してクローズ(案件化不要) → 記録として `inbound/` に残る。

## 送信側との関係

受領した要求への回答自体がアウトバウンドの要求(カウンターデマンド)になる場合、トリアージは事前入力した状態で `/demand-intake` にハンドオフします。アウトバウンドの要求書は `demand-letters/` に置かれ、このインバウンドフォルダへクロスリンクバックされます。
