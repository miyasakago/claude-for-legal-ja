# Litigation Counsel プラグイン

社内訴訟弁護士の案件ポートフォリオ管理を支援します。コールドスタートで、リスクキャリブレーション、紛争ランドスケープ、ハウススタイル — すべての案件をトリアージする基準 — をキャプチャします。統一的な intake が新規案件を構造化されたログエントリと案件ごとの履歴ファイルに変換します。ステータスロールアップと深掘りブリーフィングはログから読み取ります。

多数の案件を同時に保有し、そのほとんどを外部事務所が動かしている弁護士向けに作られています。このプラグインは案件管理システムではなく、思考のパートナーです。LawVu / SimpleLegal / Onit を使っているなら、これはそれらを置き換えません — それらと並んで、構造化された推論のレイヤーとして機能します。

**すべての出力は弁護士レビュー用のドラフトです — 引用付き、フラグ付き、ゲート付き — 法的結論ではありません。** プラグインが実務を行います: 文書を読み、プレイブックを適用し、問題を見つけ、メモを起案します。弁護士がレビュー、検証、決定します。引用は出典ごとにタグ付けされ、どれがリサーチツール由来でどれが要確認かが分かります。特権マーカーは保守的に適用され、何も偶発的に放棄されません。重大なアクション — 提出、送付、執行 — は明示的な確認の背後にゲートされます。

## 前提条件

いくつかの機能は Gmail と scheduled-tasks の統合を参照します。これらは環境に設定された MCP サーバーが必要で、同梱されていません。それらがなくても、出力は手動送付用にファイルへ書き込まれます:

- **Gmail MCP** — `/oc-status` は認証済みなら Gmail 下書きを作成、そうでなければ `oc-status/[YYYY-MM-DD]/[slug].md` のマークダウンドラフトにフォールバック。
- **Scheduled-tasks MCP** — 自動スケジューリングは同梱されていません。週次コマンドを呼び出す定期カレンダーリマインダーを設定してください。

プラグインはどちらもなくてもエンドツーエンドで動作します;統合は加算的です。

## 対象ユーザー

| Role | Primary use |
|---|---|
| **社内訴訟弁護士** | すべて — intake、トリアージ、ステータス、履歴、ブリーフィング |
| **Associate GC / Deputy GC** | ポートフォリオ監督、取締役会報告ロールアップ |
| **GC** | ポートフォリオの素早いステータス、任意の 1 案件の深掘り |

## 初回実行: コールドスタート

コールドスタート・インタビューは*ハウス*プラクティスプロファイルを書き出します — すべての案件を跨いで永続。3 つの柱:

- **リスクキャリブレーション** — アペタイト、重要性閾値、引当/開示トリガー、和解権限、保険プロファイル、重大度-確度マトリクス
- **ランドスケープ** — 会社、地理、規制ステータス、紛争パターン、頻出敵対者、外部弁護士ベンチ、社内ステークホルダー
- **ハウススタイル** — 取締役会/監査委員会メモフォーマット、引当メモフォーマット、外部弁護士指示スタイル、特権慣行、エスカレーション規範

各ステップで合理的なデフォルト(例: 3×3 重大度-確度グリッド)を提案し、すべてを自由編集可能に保ちます。書面のフレームワークをまだ持っていない場合、これがそれを明文化させるものです。

```
/litigation-legal-ja:cold-start-interview
```

設定は `~/.claude/plugins/config/claude-for-legal-ja/litigation-legal-ja/CLAUDE.md` に保管され、プラグインアップデートを跨いで残ります。

## コマンド

| Command | Does |
|---|---|
| `/litigation-legal-ja:cold-start-interview` | コールドスタート → ハウス `~/.claude/plugins/config/claude-for-legal-ja/litigation-legal-ja/CLAUDE.md` を書き出し |
| `/litigation-legal-ja:matter-intake` | 統一 intake → `matters/[slug]/` を書き出し + `_log.yaml` に追記 |
| `/litigation-legal-ja:portfolio-status` | ポートフォリオロールアップ — リスク分布、近接期限、停滞案件 |
| `/litigation-legal-ja:matter-briefing [slug]` | 1 案件の深掘りブリーフィング — GC または外部弁護士との通話前に読める状態 |
| `/litigation-legal-ja:matter-update [slug]` | 案件履歴に日付付きイベントを追記; ログの `last_updated` を更新 |
| `/litigation-legal-ja:matter-close [slug]` | アクティブポートフォリオから案件をアーカイブ(保持、削除しない) |
| `/litigation-legal-ja:demand-intake [title]` | 要求書のための起案前コンテキスト収集(支払い / 違反 / C&D / 雇用終了 / 保全) |
| `/litigation-legal-ja:demand-draft [slug]` | intake からレターを起案 — FRE 408(米国連邦証拠規則 408)/ 特権ゲートを実行、`.docx` を出力、送付後チェックリストを書き出し |
| `/litigation-legal-ja:demand-received [path]` | 受領した要求書をトリアージ — 選択肢分析、ポートフォリオクロスチェック、matter/demand-intake へハンドオフ |
| `/litigation-legal-ja:subpoena-triage [path]` | サブポエナをトリアージ — 分類、スコープ/負担/特権、異議フレームワーク、コンプライアンス計画 |
| `/litigation-legal-ja:legal-hold [slug] [--issue/--refresh/--release/--status]` | ホールドを発行、更新、解除、報告 — `.docx` を書き出し + ログを更新 |
| `/litigation-legal-ja:chronology [slug]` | 宣言済み文書出典 + アップロードから時系列表を構築/更新 — 案件セオリーに従って重要度タグ付け |
| `/litigation-legal-ja:oc-status` | ポートフォリオ全体で週次の OC ステータス依頼メールを起案; MCP 利用可能なら Gmail 下書き |
| `/litigation-legal-ja:claim-chart` | 要素チャートを構築またはレビュー — 特許クレームチャート(侵害 / 無効 / レビュー)または民事要素チャート(任意の請求原因または防御)、ギャップ検出付き |

| Skill | Purpose |
|---|---|
| **cold-start-interview** | ハウスプラクティスプロファイル — リスクキャリブレーション、ランドスケープ、スタイル |
| **matter-intake** | 統一 intake 質問; 案件ファイル + ログ行を書き出し |
| **portfolio-status** | ログを跨いだロールアップ — リスク、期限、停滞 |
| **matter-briefing** | 1 案件をファイル + 履歴から深く読む |

| **matter-close** | アーカイブのセマンティクス; 結果をキャプチャ |
| **demand-intake** | 要求書のための適応的コンテキスト収集 — 当事者、事実、レバレッジ、特権フィルタ |
| **demand-draft** | FRE 408 / 特権ゲート、`.docx` を `[CITE:___]` プレースホルダ付きで起案; 送付後チェックリストを書き出し; 案件作成を提案 |

## インタラクティブコマンド vs スケジュールされたエージェント

上記のコマンドは呼び出したときに実行 — 案件作業中向け。下のエージェントはスケジュールで実行 — 見ていない間に動くもの向け:

| Agent | 何を監視 | デフォルトのケイデンス |
|---|---|---|
| **docket-watcher** | アクティブポートフォリオの案件の裁判所ドケット — 新規提出物を取得、候補期限を計算、各案件の履歴と成果物にクロスリファレンス | 週次 |

## データの構成方法

```
litigation-legal-ja/
├── CLAUDE.md                          # ハウスプラクティスプロファイル — リスク、ランドスケープ、スタイル
├── matters/
│   ├── _log.yaml                      # ポートフォリオ台帳(案件ごとに 1 エントリ)
│   └── [matter-slug]/
│       ├── matter.md                  # 案件固有 intake + セオリー + ポスチャ
│       ├── history.md                 # 追記専用イベントログ
│       ├── chronology.md              # アドボカシー向けタイムライン(オンデマンド)
│       └── legal-hold-v[N].docx       # ホールド通知(発行、更新、解除)
├── demand-letters/                    # アウトバウンド要求
│   └── [slug]/
│       ├── intake.md
│       ├── draft-v1.docx
│       └── checklist.md
├── inbound/                           # 受領した要求、サブポエナ、規制当局レター
│   └── [slug]/
│       ├── incoming.[ext]
│       ├── triage.md
│       └── response-v1.docx           # 回答する場合
└── oc-status/                         # 週次の OC ステータス依頼ドラフト
    └── [YYYY-MM-DD]/
        ├── _summary.md
        └── [slug].md                  # 案件ごとに 1 メール
```

それぞれ別のフォルダなのは、それぞれが独立したワークフローを持つからです。案件はポートフォリオで追跡;要求書とインバウンド項目は案件に発展する場合と発展しない場合があります;OC ステータスドラフトは定期的な成果物です。関連するときは、`related_matters` フィールドと `matter.md` のクロスリンクが結びつけます。

ログが YAML なのはロールアップスキルがパース可能だから。案件ごとのファイルがマークダウンなのは、そこで読み・編集するから。両方ともプレーンテキストとしてフォルダにチェックインされます — プロプライエタリなものは何もありません。

## コネクターと引用検証

**最初にリサーチツールを接続 — 引用ガードレールはそれに依存します。** ツールなしでは、すべての引用が `[verify]` でタグ付けされ、各成果物の上のレビュアー注記が出典未検証であることを記録します。プラグインはどちらでも動作しますが、リサーチツールを接続するとより多くの検証を肩代わりしてくれます。

このプラグインの法律調査コネクターは単なるデータソースではありません — 検証済み引用と要確認引用の差です。**CourtListener**(米国判例、PACER ドケット、引用検証)、**Trellis**(州第一審裁判所データセット — ドケット、判決、評決、裁判官・相手方代理人の分析)、**Everlaw**(eDiscovery プロジェクト)、または **Aurora**(読み取り専用 Consilio eDiscovery — すべての記録は出典に紐付け)経由で取得した引用は、出典タグ付きで遡れます。モデル知識や Web 検索からの引用は `[verify]` または `[verify-pinpoint]` でタグ付けされ、依拠する前にプライマリソースに対して確認すべきです。プラグインは引用を階層化するので、検証時間が重要な箇所に投入されます。

## 統合

`.mcp.json` の一般的なコネクターバケットを同梱:

- **Slack** — メッセージ検索、チャンネル閲覧、ディスカッション検索
- **Google Drive** — ドキュメント検索、閲覧、取得

何も接続しなくても有用に設計されています。Relativity、DISCO、CLM、メールから取得したくなったら、コアアーキテクチャを変更せずに統合スキルを追加できます。

## どのように学習するか

`~/.claude/plugins/config/claude-for-legal-ja/litigation-legal-ja/CLAUDE.md` のプラクティスプロファイルは静的ではありません — プラグインを使うほど良くなります。スキルは、出力がデフォルトを使ったときにあなたが調整すべきものを伝えます。セットアップを再実行、ファイルを直接編集、または新しい立場を記録するようスキルに伝えることができます。

## 注

- すべてのスキルは最初に `~/.claude/plugins/config/claude-for-legal-ja/litigation-legal-ja/CLAUDE.md` から読みます。リスクアペタイトが変わったり新しい外部弁護士を起用したら、ここを更新してください — 個々の案件でごまかさないでください。
- `## カンパニープロファイル` は慣例的に `~/.claude/plugins/config/claude-for-legal-ja/litigation-legal-ja/CLAUDE.md` の最初のセクションです。他の `-legal` プラグインを実行している場合、同じコンテキストを再入力する代わりにコピーできます。
- `_log.yaml` はポートフォリオ状態の真の情報源。クリーンに保ってください。
- 案件履歴は追記専用。何かが間違っていた場合、訂正を新規エントリとして注記してください — 過去を編集しないでください。
- クローズした案件は `_log.yaml` に残ります(検索可能な履歴)。`/portfolio-status` はデフォルトでアクティブロールアップから除外します。

## インラインマーカーの慣行

3 つのマーカーがスキル出力とドラフトに現れます。これらはディスクレーマではなく、アクション項目です:

- `[CITE: specific cite needed]` — 法的権威のプレースホルダ。弁護士が送付前に埋めるか確認します。
- `[VERIFY: specific fact]` — 出典に未確認の事実主張。弁護士が依拠前に検証します。
- `[SME VERIFY: specific judgment call]` — 主題専門家のレビューを要する判断(メリット読み、重要度タグ、異議の強さ、特権ステータス)。SME = 関連法域 / エリアで資格を持つ弁護士。寛大に使用 — 判断重のものはこれを携帯すべきです。

未解決マーカーを持つドラフトやトリアージは、どれだけ磨かれて読めても最終ではありません。
