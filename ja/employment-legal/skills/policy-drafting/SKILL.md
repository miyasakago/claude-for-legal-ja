# /policy-drafting

1. `~/.claude/plugins/config/claude-for-legal-ja/employment-legal-ja/CLAUDE.md` をロード → 法域フットプリント、ハンドブック所在。
2. 下記のワークフローを使用。
3. コアポリシーをドラフト。フットプリントの各法域について必要なバリアントをチェック。
4. 出力: コアポリシー + 州別補足。法律が現在シフトしている箇所をフラグ。

---

## 案件コンテキスト

**案件コンテキスト。** プラクティスレベル CLAUDE.md の `## 案件ワークスペース` を確認。`Enabled` が `✗` の場合(インハウスユーザーのデフォルト)、このパラグラフの残りはスキップ — スキルはプラクティスレベルのコンテキストを使用し、案件機構は見えません。有効でアクティブな案件がない場合、尋ねる: 「これはどの案件のものですか? `/employment-legal-ja:matter-workspace switch <slug>` を実行、または `practice-level` と言ってください。」案件固有のコンテキストと上書きについてアクティブ案件の `matter.md` をロード。出力は案件フォルダ `~/.claude/plugins/config/claude-for-legal-ja/employment-legal-ja/matters/<matter-slug>/` に書き込み。`Cross-matter context` が `on` でない限り、他の案件のファイルを決して読まない。

## 目的

カリフォルニアで正しいポリシーは、テキサスでは間違い(または不要)かもしれません。このスキルはコアポリシーをドラフトし、フットプリントが異なるルールを要求する場合に州別補足を生成します。

## コンテキストをロード

`~/.claude/plugins/config/claude-for-legal-ja/employment-legal-ja/CLAUDE.md` → 法域フットプリント、ハンドブック所在とフォーマット。

## ワークフロー

### Step 1: ポリシーのスコープ

- ポリシーは何のため? (リモートワーク、育児休暇、ソーシャルメディア等)
- なぜ今? (法的要件、インシデント、成長、ギャップに気付いた)
- 誰に適用? (全従業員、特定の役割、特定の所在地)

### Step 2: 法域スキャン

フットプリントの各州/国について、チェック: この法域はこのトピックに関する特定のルールを持つか?

**法域差のある共通トピック:**

| トピック | 差 |
|---|---|
| 有給休暇 | 州の義務(CA、NY、CO、WA 等)で累積率、用途、繰越が異なる |
| 育児休暇 | 州プログラムが FMLA(米国家族・医療休暇法)の上に重なる(CA PFL、NY PFL 等) |
| 食事と休憩 | CA は外れ値(ペナルティペイ); 多くの州は最小限 |
| 経費精算 | CA は要求; 多くの州は要求しない |
| 給与透明性 | 求人広告でレンジを要求する州のリストが拡大中 |
| 非競業 | hiring-review スキル参照 — 一部州で執行不能 |
| 最終給与 | タイミングが広く異なる |

トピックに法域差がない(例: ドレスコード)場合、このステップをスキップ。

### Step 3: コアポリシーをドラフト

1 つのポリシー。どこでも適用。明確で読みやすく — 従業員が弁護士なしで理解すべき。

構造:
- 目的(1 文 — このポリシーが存在する理由)
- スコープ(誰に適用)
- ルール(何が要求/許容/禁止か)
- プロセス(どう要請、誰が承認、もし [X] なら)
- 質問(誰に尋ねるか)

避ける: 「here for」、「notwithstanding」、ネストされた例外。これはハンドブックポリシーで、契約書ではない。

### Step 4: 州別補足

ルールが異なる各法域について、補足:

```markdown
### [State] Supplement

[State] で働く従業員は、コアポリシーに加えて / の代わりに以下に従います:

- [Specific difference]
- [Cite the state law if helpful]
```

補足はタイトに保つ。差分のみ — コアを繰り返さない。

### Step 5: クロスチェック

- このポリシーはハンドブックに既にあるものと矛盾するか?
- 会社が提供する意図以上を約束するか? (ポリシーは約束 — 裁判所はハンドブックの約束に雇用主を縛る。)
- 不注意に契約を作るか? (一部の州はハンドブックポリシーを契約として扱う — ハンドブックがまだ持っていなければ標準の「これは契約ではない」文言を含める。)

## 出力

```markdown
# [Policy Name]

## Core Policy

[Full text]

## State Supplements

### [State 1]
[Supplement]

### [State 2]
[Supplement]

---

## Drafting Notes (internal — remove before handbook insertion)

- **Jurisdictional scan:** [チェックした州、差分のある州]
- **Conflicts with existing handbook:** [none | list]
- **Law currently shifting:** [この件が流動的な州があれば]
- **Review cadence:** [いつ再訪 — 年次、または X が発生したとき]
```

> **ドラフトで、施行中のポリシーではない。** これは弁護士レビュー用のドラフト支援で、公開できるポリシーではない。ハンドブックポリシーを公開することは法的結果を持つ — 複数の州で会社を契約上の約束に縛り、賃金/休職/配慮ポリシーは雇用主に対して定常的に読まれる。あなたの法域の有資格の弁護士、ソリシター、バリスター、または他の認定法務専門家がレビューし、必要に応じて編集し、ポリシーが展開される前に専門的責任を負う。このドラフトをレビューなしで公開または配布しないこと。

## 引き渡し

handbook-updates スキルへ: このポリシーが承認されたら、それを現行ハンドブックと差分比較して何が変わるかをフラグ。

## このスキルが行わないこと

- ポリシーを承認。ドラフトする; 人間が承認する。
- ポリシーを展開。従業員への伝達は HR ワークフロー。
- 地上のすべての法域をカバー — フットプリントのもののみ。フットプリントが拡大したら再実行。
