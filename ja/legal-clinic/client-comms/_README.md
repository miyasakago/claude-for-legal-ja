# client-comms/ — 案件ごとのコミュニケーションログ

案件 1 件につき 1 フォルダ。フォルダ内に、`log.md`(クライアントとのすべてのやり取り — 受信・発信、電話・メール・テキスト・書面・対面会議すべてを記録した連続ログ)を保持します。`/legal-clinic-ja:client-comms-log` が作成・追記します。

## レイアウト

```
client-comms/
├── _README.md                     # このファイル
└── [case-id]/
    └── log.md                     # 追記専用の連続ログ
```

## スラグ

案件を識別する ID(インテイク記録、`deadlines.yaml` の `case_id`)と一致させます。1 案件 = 1 フォルダ。

## なぜ存在するか

- **マルプラクティス(過誤責任)防御** — 「日付 Y に X を伝達した」という記録が必要。
- **引継ぎ時の継続性** — 引き継ぐ学生がログを読めば、クライアントへの再ヒアリングなしに事案の経緯を理解できる。
- **パターンの可視化** — 6 週間で 5 件のボイスメール未対応は監督上のフラグ。
- **クライアントファイルの保存義務** — ロースクールのクリニックには保存義務があり、本ログは完全なファイルの一部となる。

## ログエントリの形式

```markdown
## [YYYY-MM-DD HH:MM] — [in / out] — [medium]

**Who (student):** [氏名]
**Who (client side):** [クライアント名。相手方弁護士などからの電話の場合は第三者を記載]
**Duration / length:** [10 分の通話 | 3 段落のメール | 2 ページのレター]

**Summary:**
[何があったか、2 ~ 4 文で。実体内容に加え、トーンが重要な場合はそれも記載。]

**Action items:**
- [学生がクライアントに対して負う事項、期限付き]
- [クライアントが学生に対して負う事項、想定タイミング付き]

**Follow-up due:** [該当する場合は日付]

**Notes:**
[上記の枠に入らないが重要な事項 — 使用言語、観察された家族関係の力学、クライアントの不安レベルなど]
```

## このフォルダに含めない情報

- 実体的な案件分析(インテイク/メモ/ステータスのファイルに記載する)
- 文書のドラフト(別途の案件フォルダに保存する)
- 秘匿特権のある弁護士限定メモ(クリニックの内部案件メモ用の場所に保管する)

コミュニケーションログは事実としての連絡記録であり、法的成果物ではありません。実体内容はログに、戦略と分析は別の場所に — を徹底してください。

## 保存

追記専用。過去のエントリを編集してはいけません — 誤りや明確化が必要な場合は、古いエントリを参照する新しいエントリを追加します。何を、いつ言ったかの記録はクライアントファイルの一部であり、歴史を書き換えることは本ログの目的を損ないます。
