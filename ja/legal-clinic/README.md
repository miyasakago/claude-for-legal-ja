# Claude for Law School Clinics(ロースクール・リーガルクリニック用 Claude)

*AI 対応の臨床法学教育を通じて司法アクセスを強化する。*

ロースクール・リーガルクリニック向けのプラグイン — 臨床指導教授の監督下で、ロースクール生が代理人を雇えない人々に無償の法的サービスを提供する機関です。在留資格(immigration)、住居(housing)、家族法、消費者保護、刑事弁護、公民権など。

**すべての出力は、学生の分析と弁護士のレビュー前提のドラフトです — マーキング、ゲーティング、ログ取得が行われます。プラグインは作業の足場を作り、学生はそれを推論し、指導弁護士がレビューします。教授がセットアップで設定した監督モデルを通さずに、何もクリニックを出ません。**

## このプラグインが解決する問題

クリニックは構造的に容量制約を受けています。指導教授は 5 ~ 10 名の学生を管理し、各学生は授業との両立のなかで複数案件を抱え、学生は学期ごとに入れ替わります。インテイクの書き起こし、初稿作成、リサーチ起点、ステータス更新といった事務作業がクライアント助言に充てるべき時間を消費しています。結果として、長い待機リスト、限られた案件数、待ちきれず諦める人々が生まれます。

このプラグインは、ロイヤリング(lawyering / 弁護士業務)*の周辺* にある時間コストを削減し、同じ学生・教授がより多くのクライアントを意味ある形でサポートできるようにします — 学生はまた、臨床教育を価値あるものとする分析と戦略により多くの時間を割けます。

**非教育的部分を加速し、分析的作業は温存する。** これが設計原則です。

## 使う人

| 役割 | 実行するもの | 得られるもの |
|---|---|---|
| **指導教授** | `/cold-start-interview`(一度きり)、`/supervisor-review-queue`(正式レビューを有効にした場合) | クリニックコンテキスト設定済み、学生作業のレビュー |
| **学生** | `/ramp`(学期開始時)、その後 `/client-intake`、`/draft`、`/memo`、`/research-start`、`/status`、`/client-letter` | スタート点 — 完成成果物ではない |

## コマンド

| コマンド | 何をするか | 何をしないか |
|---|---|---|
| `/cold-start-interview` | **教授。** クリニックの 1 回限り設定: プラクティスエリア、法域、監督スタイル、ハンドブック/規則のアップロード | — |
| `/build-guide` | **教授。** プラクティスエリア別ガイドの作成: インテイク質問、教育ポスチャー(assist / guide / teach)、レビューゲート、クロスプラグインチェック | `/cold-start-interview` を置き換えない — これは 1 つのプラクティスエリア向けにスキルを調整するもの |
| `/ramp` | **学生。** 学期オンボーディング: クリニックの手順、ツールウォークスルー、練習エクササイズ | 教授のオリエンテーションを置き換えない |
| `/client-intake` | 構造化インテイク: プラクティスエリア別テンプレート、クロスエリア論点発見、利益相反フラグ、トリアージ | 案件を受任するかの判断はしない |
| `/draft [doc]` | 初稿: 庇護申請、立退き答弁書、保護命令、要求書 — 法域認識あり | 完成成果物は生成しない |
| `/memo` | IRAC 骨組みの案件分析、リサーチギャップをフラグ | 分析は書かない — 骨組みを与える |
| `/research-start [issue]` | リサーチロードマップ: 法令、判例領域、Westlaw 検索語 | **典拠ではなくリード** — 学生はすべて検証する |
| `/status [audience]` | 案件ステータス要約: クライアント向け、内部向け、裁判所提出可 | 提出はしない |
| `/client-letter [type]` | 定型コレスポンデンス: アポイント確認、書類請求、簡易進捗 | 実体的助言は行わない — それは `/status client` または会話で |
| `/deadlines` | 案件期限の追跡 — 追加、案件横断ロールアップ(14/7/3/1 日前警告)、超過フラグ | 起算事由から期限を計算しない; 学生がローカルルールに従って計算する |
| `/client-comms-log [case]` | 案件ごとの追記専用コミュニケーションログ — 電話、メール、書面、対面 | 実体的法的分析は保存しない; あくまで連絡記録 |
| `/semester-handoff` | 学期末オフボーディング — 次コホート向けの案件ごとの引継ぎメモ | 案件をクローズしない; 学期末に終わる案件は最終 `/status internal` メモを得て引継ぎ文書でクローズとマークされる |
| `/supervisor-review-queue` | **教授、正式レビュー有効時。** 待機中のもの、承認/編集/差戻し | オプショナル — 3 つの監督モデルの 1 つ |

## 倫理・秘密保持上の前提条件

実際のクライアント案件で本プラグインを使う前に、クリニックの指導弁護士および学校の IT / 倫理オフィスと、以下を確認してください:

1. **あなたの Claude アカウントの階層と、そのデータ保存・学習方針。** Team、Enterprise、Work、Education、個人アカウントは、保持、学習利用、サブプロセッサーの扱いについて異なる保証を持ちます。クリニックのアカウントに適用されるものを確認してください。
2. **AI 支援作業に関するクライアント同意・開示の実践** — ABA Formal Opinion 512(2024、米国弁護士会公式意見 / 弁護士による生成 AI 利用に関する指針)、所在州の弁護士会の AI ガイダンス(あれば)、および Model Rules 1.1(競争)、1.4(コミュニケーション)、1.6(守秘義務)、5.3(非弁護士補助者の監督)に従う。クリニックが AI 利用をクライアントに開示するか、どう開示するかを決定し、文書化する。
3. **秘匿特権・秘密情報の取り扱い** — セッションに何を貼り付けるか、出力をどこに保存するか、誰がアクセスするか、どれだけ保存するか、学生入れ替わりがアクセスにどう影響するか。
4. **クリニックのプラクティスエリアの一部が高度な秘密性を要するか**(在留資格、刑事弁護、DV(domestic violence / 家庭内暴力)、一部の家族法・公民権案件)— 追加のセーフガードが必要か、当該案件種別ではプラグイン自体を使わないかを決定する。

このステップは省略しないでください。コールドスタート・インタビュー(`/legal-clinic-ja:cold-start-interview`)が、他の構成の前に Part 0 としてこれらの決定をキャプチャします。

## 信頼度マーカー

本プラグインのスキルはインラインで信頼度をフラグするので、学生と指導弁護士は足場が不確かな箇所と主張している箇所を見分けられます。すべてのマーカーは検証を促すプロンプト — マークされたものは信用されていません。

- `[AI-ASSISTED DRAFT — requires student analysis and attorney review]` — すべての出力に適用されるベースラインラベル。レビューラベルであり、クライアント向けコンテンツの一部ではない; 外部に出る前に取り除く。
- `[UNCERTAIN: specific reason]` — スキルがこの判断について本当に不確か(少数説、議論のある問題、スキルがよく知らない法域)。memo、intake、status、draft で使用。
- `[VERIFY: claim — check source]` — もっともらしいが未検証の主張。学生は依拠する前に確認する必要 — 引用、ローカル規則フォーマット、規則記述など。research-start、draft、status、memo で多用。
- `[RESEARCH NEEDED: ...]` — memo 骨組みのマーカーで、規則記述がリサーチギャップ(結論ではない)であることを示す。学生が `/research-start` を実行して埋める。
- `[STUDENT ANALYSIS: ...]` — memo 骨組みのマーカーで、適用部分は意図的に空。学生の推論で埋める。
- `[STUDENT CONCLUSION: ...]` — memo 骨組みのマーカーで、結論は意図的に空。
- `[FACT NEEDED: ...]` — draft 骨組みのマーカーで、案件ノートに必須事実が欠けている。学生がその事実を入手; 推測しない。
- `CHECK WITH [PROFESSOR] BEFORE SENDING` / `BEFORE FILING` — 「構成可能フラグ」監督モードで、フラグ対象トピックの出力に付ける監督フラグラベル。

フラグの **不在** よりもフラグの **存在** を信頼してください。フラグなしの記述はスキルが自信を持っていることを意味するが、学生や弁護士が検証を省くべきことは意味しない。ABA Formal Opinion 512 はいずれにせよ検証を要求する。

## 組み込みセーフガード

各スキルのすべての出力に含まれるもの:

- **AI 支援ラベル** — 学生の分析と弁護士のレビューが必要
- **信頼度インジケータ** — 本当に不確かな場所には `[UNCERTAIN: ...]`(推測ではなく)
- **検証プロンプト** — 出力に依拠する前に事実確認すべき具体的事項
- **タスクに合わせた倫理リマインダー**

これらは臨床教育モデルを補強するよう設計されています: 学生が考え、プラグインがその周りの重い作業を担う。

**リサーチ出力について特に:** `/research-start` は学生が検証・発展させるためのリードとフレームワークを提供します。明示的に **典拠としての法的引用は提供しません**。これは倫理的セーフガードであると同時に教育的特徴 — 学生はリサーチと判断を学び続けるが、より良い出発点から始められる。

## 監督ワークフロー(構成可能)

正式レビューワークフロー(学生ドラフト → 教授レビュー → 承認)をプラグインに含めるかは、本当に開かれた問いです。クリニックによってはハードゲートを望み、別のクリニックは自身の監督構造には過剰に処方的と感じます。

コールドスタート・インタビューは教授に選択を求めます:

1. **Formal review queue(正式レビューキュー)** — クライアント向け/裁判所向け出力がキューに入り、教授が承認、すべて記録
2. **Configurable flags, informal review(構成可能フラグ、非公式レビュー)** — 特定のトリガーで「CHECK WITH PROFESSOR」ラベルを付ける、キュー機構なし
3. **Lighter-touch(軽め)** — 標準セーフガードラベルをすべてに付け、教授は既存のクリニック構造(case rounds、1on1)を通じて監督

`~/.claude/plugins/config/claude-for-legal-ja/legal-clinic-ja/CLAUDE.md` を編集して後から変更可能。あなたの設定はそのバージョン非依存パスに保存され、プラグインアップデートを越えて存続します。

## 学期入れ替わり: `/ramp` という解

学期ごとにクリニックはゼロから再構築されます。新しい学生は手順、ツール、プラクティスエリアの基礎を学ぶのに数週間必要。`/ramp` はインタラクティブなオンボーディング — セットアップで教授がアップロードしたクリニックハンドブックを読み、低リスクの練習エクササイズ(模擬インテイク、練習ドラフト、リサーチロードマップ)を伴って教えます。学生は実際の案件に触れる前に練習できます。

`/ramp --card` は 1 ページの学生リファレンスカードを生成します: コマンド、Claude が支援できること/できないこと、検証習慣。初日に配布。

## フレームワーク: ABA Formal Opinion 512(2024、米国弁護士会公式意見 512)

本プラグインが運営される倫理フレームワーク。弁護士は生成 AI を使用してよいが、技術への能力(competence)、秘密保持、出力の監督、適切な場面でのクライアントへの AI 利用の伝達、依拠前の検証を確保しなければならない。上記のセーフガード — ラベル、信頼度インジケータ、検証プロンプト、リサーチ出力の典拠性の明示的否定 — はこのモデルのために構築されています。

臨床指導教授は、専門職責任について法学教育で最も思慮深い人々の中にいます。本プラグインは彼らが望むように動作するよう設計されています。

## コネクターと引用検証

**最初にリサーチツールを接続 — 引用ガードレールはそれに依存する。** 接続しないと、すべての引用に `[verify]` タグが付き、成果物の上の reviewer note がソース未検証であることを記録します。プラグインはどちらの方法でも動作; リサーチツールが接続されている場合、より多くの検証を肩代わりするだけです。

本プラグインのリーガルリサーチコネクターは単なるデータソースではない — 検証済み引用と確認が必要な引用の違いです。**CourtListener**(Free Law Project の米国判例と PACER ドケット)や **Descrybe**(一次法令検索、引用検索、引用文言検証)から取得された引用はソースタグ付きで遡れます。モデル知識または web 検索からの引用は `[verify]` または `[verify-pinpoint]` タグ付きで、誰かが依拠する前に一次ソースに対して確認する必要があります。プラグインは引用を階層化し、検証時間が重要な場所に向かうようにします。

## インテグレーション(オープン質問)

`.mcp.json` に一般カテゴリのコネクター一式を同梱:

- **Slack** — メッセージ検索、チャンネル閲覧、議論発見
- **Google Drive** — 文書の検索、閲覧、取得

Clio はオプショナルな将来統合として記載 — 120 以上のロースクールが Clio をケース管理に使用。ファイルアップロードから始め、Clio コネクターを使えば `/client-intake` と `/status` がケースデータを直接プルできるようになります。

クライアント秘密性のためのアカウント階層(Team vs. Enterprise)は、各クリニックの IT・倫理レビュー向けのオープン質問。Cowork のデスクトップアーキテクチャはデータをローカルで処理します。

## 学習のしかた

`~/.claude/plugins/config/claude-for-legal-ja/legal-clinic-ja/CLAUDE.md` のプラクティスプロファイルは静的ではありません — プラグイン利用とともに改善します。スキルは出力がデフォルトを使い、調整すべき点を伝えます。セットアップを再実行する、ファイルを直接編集する、または新しいポジションを記録するようスキルに指示できます。

## 前提条件

一部の機能は外部統合(ドキュメント管理、ローンチトラッカー、eDiscovery、ケース管理、規制フィード)を参照します。これらは同梱されていません — 環境に MCP サーバーがあれば、該当機能はそれを使用。なければ、プラグインはファイルアップロードと手動ワークフローにフォールバックします。`/legal-clinicgrations` を実行して環境内で何が利用可能か確認できます。
