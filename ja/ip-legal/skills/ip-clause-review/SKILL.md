# /ip-clause-review

契約書中の IP 条項を `~/.claude/plugins/config/claude-for-legal-ja/ip-legal-ja/CLAUDE.md` のプラクティスプロファイルに照らしてレビューします。譲渡ギャップ、所有権の曖昧さ、ライセンス範囲の問題、IP 保証/補償の問題をフラグします。リスク優先順位付きの per-clause 発見と、適切な場合の提案レッドライン文言を含むメモを生成します。

## 指示

1. **`~/.claude/plugins/config/claude-for-legal-ja/ip-legal-ja/CLAUDE.md` をロード.** プレースホルダーがあれば停止して促します: 「先に `/ip-legal-ja:cold-start-interview` を実行してください — IP 条項をプラクティスプロファイルに照らしてレビューする前に学ぶ必要があります」。

2. **契約書を取得:** ファイルパス、Drive リンク、または貼り付けテキストから。提供がなければ尋ねます。

3. **下記のワークフローに従います.** 特に:
   - 契約タイプと IP について自社がどちら側か(供与 / 受領 / 両方)を確立。サイドの質問は文書単位で、一度きりのセットアップ回答ではありません。
   - 契約が雇用、業務委託、SOW、または職務著作物の場合、まず譲渡ギャップ・チェックを実行。
   - リスク優先順位付きの per-clause 発見を生成。
   - 条項間の整合性をチェック(条項単位だけでなく)。
   - 法域上の含意(著作者人格権、職務著作物、黙示的ライセンス、特許補償)を注記。

4. **メモを下記テンプレートで出力** — work-product ヘッダーを最初、ボトムライン、譲渡ギャップ・チェック、重大度別条項、整合性フラグ、法域注記、承認ルーティング。

5. **決断スタンスを尊重.** 条項が IP をどちらにも割り当てうる解釈ができる場合、弁護士レビューのためフラグし、両方向に切れる要因を表面化します。主観的割り当て問題をサイレントに決定しないこと。

## 例

```
/ip-legal-ja:ip-clause-review ~/Documents/vendor-sow.pdf
/ip-legal-ja:ip-clause-review https://docs.google.com/document/d/...
/ip-legal-ja:ip-clause-review
```

## 目的

契約書中の IP 条項を読み、各条項が何をしているか、市場やチームの標準的な立場からどう逸脱しているか、リスクは何か、適切な場合に提案する具体的なレッドラインを弁護士に伝えます。目標は、弁護士が 1 パスで対応できるメモです。

**ほとんどの契約で最も重要な条項は IP の所有権と譲渡です.** これらは後で修正するのが難しい。雇用契約や業務委託契約でクリーンな譲渡を得られないと、M&A デューデリ、資金調達、契約締結から何年後かの訴訟で表面化します。譲渡文言が弱いまたは欠如している文書なら、メモの最上部でラウドにフラグ — 他の項目に紛れた 1 行として埋めないこと。

## 前提条件: プラクティスプロファイルをロード

**契約を読む前に、`~/.claude/plugins/config/claude-for-legal-ja/ip-legal-ja/CLAUDE.md` を読みます.** ない場合またはプレースホルダーが残っている場合は、停止して `/ip-legal-ja:cold-start-interview` を実行してください。プラクティスプロファイルから:

- 法域フットプリント — 著作者人格権の放棄が執行可能か、職務著作物が適用されるか、黙示的譲渡がギャップを埋めるか、ライセンス許諾はどれだけ広くできるかに影響
- 誰がどの重大度で逸脱を承認するか
- 出力に付与する work-product ヘッダー

## ワークフロー

### Step 1: 方向付け

契約全体を一度、素早く読みます。回答:

| 質問 | 回答 |
|---|---|
| これはどんな契約? | 雇用 / 業務委託または SOW / ベンダー MSA / インライセンス / アウトライセンス / 共同またはJDA / 和解 / 買収または資産譲渡 / その他 |
| IP について自社はどちら側? | 権利を供与または受領 / IP を譲渡または取得 / ライセンサーまたはライセンシー |
| 相手方は誰? | 名前、洗練度 — 個人、スタートアップ、BigCo |
| IP に対して具体的に対価が流れるか? | 給与、フィー、ロイヤルティ、前払い金、エクイティ、なし |
| 準拠法と裁判管轄 | 何と書かれているか — そしてプラクティスプロファイルでその法域がエスカレートまたは never としてフラグされているか? |

サイドの質問は文書単位で、一度きりのセットアップ回答ではありません。インハウス・カウンセルが雇用契約をレビューするときは「受領」側、同日にアウトライセンスをレビューするときは「供与」側。スタンスが反転します。

サイドが曖昧な場合(両当事者が貢献し両者が権利を受領する共同契約、フロースルー IP のリセラー契約)、尋ねます:

> この契約の IP について、[会社] はどちら側ですか? 権利を供与、受領、または両方? 両方なら、各方向を別々にレビューします。

### Step 2: 譲渡ギャップ・チェック(最優先)

契約が雇用契約、業務委託契約、SOW、職務著作物契約、または会社が相手方の IP の成果物への譲渡を受けるべき何かなら — まず譲渡文言をチェックします。

以下を探します:

- **現在形の譲渡**(「hereby assigns」または「hereby irrevocably assigns and agrees to assign」)。素の「agrees to assign」は譲渡の約束であって譲渡ではなく、完全化のために第二の文書を要求しうる。
- **範囲** — 関与中に作成されたすべての IP をカバーするか、会社のビジネスに関連する IP のみか、会社のリソースを使って作成された IP のみか? 成果物が広く及ぶと予想される場合、狭い範囲はギャップ。
- **著作者人格権の放棄**(著作者人格権を認める法域 — EU 加盟国、カナダ、他多数 — 米国は視覚芸術に対し狭く認める)。契約が著作者人格権の法域に準拠するか相手方がそこにいるなら、放棄または不主張の誓約が重要。
- **Further assurances** 条項 — 相手方は後で譲渡を完全化するために必要な他のものに署名することに同意。
- **既存 IP のカーブアウト** — 相手方は譲渡から何を除外するか、そのリストは具体的か open-ended か?

上記のいずれかが欠落または弱い場合、メモの最上部で 🔴 または 🟠 の重大度と具体的なレッドラインでフラグします。

```markdown
## ⚠️ ASSIGNMENT GAP

**Section [X]** は成果物の IP を譲渡しますが: [具体的な問題 — 例:
"'hereby assigns' ではなく 'agrees to assign'"、または「著作者人格権の放棄なしで
準拠法はフランス」、または「カーブアウトリストが提供されず、相手方は既存の
プラットフォーム IP を持つ」]。

**Risk:** これは M&A デューデリで何年も後に表面化するギャップ。
相手方(または承継者)は、私たちが所有していると思った成果物に残余権を持つ
可能性があります。

**Proposed redline:**
> "[具体的な置換文言]"

**Escalation:** `~/.claude/plugins/config/claude-for-legal-ja/ip-legal-ja/CLAUDE.md`
の通り、譲渡範囲のギャップは [approver] にエスカレート。
```

> **譲渡で AI 生成コンテンツを移転できるか?** *Thaler v. Perlmutter* と著作権局の 2023 年 AI 登録ガイダンスは、人間の創作なしの AI 生成物は著作権で保護されない可能性を示唆しますが、境界は不明確で進化する領域です。コントラクターが成果物の実質的部分に AI を使用するなら、その部分の著作権ステータスは不確実 — 譲渡条項は存在する権利のみを移転できます。
>
> チェック: 契約に AI 使用の開示義務はあるか? 成果物における AI の役割についての表明はあるか? どの部分が AI 支援か対 人間執筆かを識別するメカニズムは?
>
> 不在で AI 支援作成が予見可能なら(業務委託、開発、コンテンツ作成、デザイン): 🟠 High。「譲渡条項はよくドラフトされているが、AI 使用開示がない。AI 生成コンテンツの著作権ステータスは未確定で、開示義務がなければどの部分が影響を受けるか分かりません。AI 使用の表明と開示義務を追加してください」。`[review — copyright status of AI-generated works is an evolving area; verify against current Copyright Office guidance and case law]`

> **AI 支援発明者性.** 不正な発明者で出願された特許は執行不能です。コントラクターが発明的概念に貢献する AI ツールを使うと、発明者性問題は未確定で特許がリスクにさらされます。特許可能な成果物をカバーする特許譲渡規定を持つ任意の契約について:
>
> チェック: 契約に AI 使用の表明はあるか? AI が貢献した場合の発明者性判定プロセスは? 発明プロセスでの AI 使用についての開示義務は?
>
> 不在ならフラグ。「AI 使用表明なしの特許譲渡。AI ツールが発明的概念に貢献したら、発明者性判定が複雑になり、誤って帰属された特許は執行不能です。AI 使用表明と発明者性プロトコルを追加してください」。

### Step 3: 条項単位のレビュー

IP に関連する各条項について、ブロックを生成します。探すべき条項:

- **譲渡 / 職務著作物** — 契約下で作成されるものを誰が所有するか
- **成果物の所有権** — 譲渡とは別。しばしば契約のアウトプットを述べる
- **改良物と派生物** — 既存 IP の改良物、派生著作物を誰が所有するか
- **バックグラウンド IP vs フォアグラウンド IP** — 契約は既存 IP と新規作成 IP を別々に定義し、必要な範囲で BG IP をライセンスするか?
- **ライセンス許諾** — 範囲、独占性、地域、使用分野、サブライセンス可能性、期間、解除トリガー、ロイヤルティ/フィー構造
- **IP 保証** — 第三者権利の非侵害、許諾権限、オリジナル著作物
- **IP 補償** — 範囲、上限、手続、例外(ユーザー改変、組み合わせ、不正使用)
- **著作者人格権の放棄** — 法域依存
- **オープンソース表明** — どの OSS が成果物に組み込まれており、組み込まれていないかについての表明
- **商標使用** — 相手方のマークの使用に関する許諾または制限、ブランドガイドライン、ライセンサー向け品質管理
- **秘密保持 / 営業秘密** — 営業秘密素材の扱い、合理的措置、返却または破棄、契約後義務

存在する各条項について、以下を生成:

```markdown
### [Section X.X]: [条項名]

**What it says:** [平易な言葉でのサマリー、1〜2 文]

**What's market (この契約タイプ、このサイド、この法域について):**
[簡潔な参照点]

**Risk:** 🔴 Critical | 🟠 High | 🟡 Medium | 🟢 Low

**Why it matters:** [1〜2 文 — このままだとビジネスで何がうまくいかないか]

**Proposed redline (必要なら):**
> "[具体的な置換文言]"

**Decision call:** [条項が意図する IP 配分を達成しているか不確実なら、
弁護士レビューのためフラグし、両方向に切れる要因を述べる。
主観的配分問題をサイレントに決定しないこと。]
```

**重大度キャリブレーション:**

| レベル | 意味 |
|---|---|
| 🔴 Critical | 修正せずに署名しないこと。譲渡ギャップを持つべき文書での譲渡ギャップ。狭いものが意図された場所での無制限ライセンス。非排他が意図された場所での排他許諾。 |
| 🟠 High | 強く押す。動かなければエスカレート。曖昧な範囲、人格権法域での放棄欠如、further assurances 欠如、狭い補償。 |
| 🟡 Medium | 第一ラウンドでは押す。最後のオープン項目なら受け入れる。表面的だが不正確な文言、標準より短い存続期間。 |
| 🟢 Low | 注記する。資本を費やさない。配分を変えない様式的逸脱。 |

### Step 4: 条項間の整合性

IP 条項はシステムとして失敗します。チェック:

- **ライセンス許諾はライセンスされるものの範囲に一致するか?**(「使用」のライセンスは「使用、改変、派生著作物作成」のライセンスより狭い。)
- **保証は許諾がカバーするすべてをカバーするか?**(著作権と営業秘密もカバーするライセンスで特許に限定された非侵害保証はギャップを残す。)
- **補償は保証が約束するものをカバーするか?**(補償なしの保証は救済なしの約束。)
- **解除はライセンスを引き戻すか?**(またはペイドアップ・ライセンスは解除を生き残るか? どちらも擁護可能 — 質問は意図に一致するか。)
- **この契約と関連 SOW、オーダーフォーム、または関連サイドレターとの IP 配分は一貫しているか?** コンフリクトをフラグ。

### Step 5: 法域注記

IP ルールは法域固有で、結果を変える方法で違います。契約が以下のいずれかに関与する場合フラグ:

- **著作者人格権** — EU 加盟国、カナダ、シビルローの世界の多くは、完全に譲渡または放棄できないかもしれない人格権(paternity、integrity)を認めます。米国の認知は狭い(VARA、視覚芸術用)。
- **職務著作物** — 米国ドクトリンは制定法(17 U.S.C. § 101)で、独立コントラクター向けには列挙されたカテゴリにのみ適用。UK は雇用文脈で譲渡を黙示しますが、コントラクターには必ずしも。シビルロー法域はまた異なります。
- **黙示的ライセンス** — コモンロー法域は書面許諾が沈黙する場所で黙示的ライセンスを読み込むかもしれない。シビルロー法域は通常そうしない。
- **特許補償の例外** — 組み合わせ、改変、ユーザー供給の被告機能は標準的な米国例外。EU 特許と UPC との相互作用は発展中。

契約が準拠する法域を述べ、プラクティスプロファイルがその法域を standard、escalate、never としてフラグするかを述べる。

## レッドラインの粒度

**可能な限り最小の粒度で編集してください.** レッドラインは交渉のアーティファクトで、書き直しではありません。条項の wholesale 置換は「我々はあなたのドラフトを捨てた」というシグナル — 攻撃的で、相手方に条項全体を再読させ、彼らのドラフトの問題ない部分も捨てます。外科的レッドライン — 単語を消す、フレーズを挿入、サブクローズを再構成 — は「我々には具体的な要求がある」とシグナルし、読み、理解し、受け入れるのが速い。

プレイブックの立場を達成する最小の編集にデフォルト:
- フレーズより **単語** を置換。(「twelve (12)」 → 「twenty-four (24)」)
- 文よりも **フレーズ** を置換。(「paid by the Buyer」 → 「paid and payable by the Buyer」)
- 文を置換するより **サブクローズ** を再構成。(複合条件を分けるために (a) と (b) を追加。)
- 条項より **文** を置換。
- 相手方のバージョンが立場から大きく離れていて外科的編集のほうが新たなドラフトより読みにくくなる場合のみ **条項全体** を置換 — その場合、送付状で述べる: 「変更が広範であったため、§8.2 をマークアップではなく置換しました。差分を歩いて説明できます」

迷ったら、より小さく。外科的レッドラインを受け取ったクライアントは、注意深く読んだと信頼します。wholesale 置換を受け取ったクライアントは、まったく読んだのか疑います。

### Step 6: メモを組み立て

`~/.claude/plugins/config/claude-for-legal-ja/ip-legal-ja/CLAUDE.md` → `## Outputs` の work-product ヘッダーを付与します(Role により異なる — `## Who's using this` 参照)。

このメモと underlying 契約は特権付き、機密、または両方かもしれません。出力はソースからそのステータスを継承します。特権サークル内でのみ配布。特権素材があるところでマークし保存。外部配布前に work-product ヘッダーを剥がします。

> **No silent supplement.** 設定された法律調査ツールへのクエリーが、メモに必要なルール(ある法域での人格権放棄の執行可能性、黙示的ライセンスの範囲、IP 保証の存続期間の基準)について少数のまたはゼロの結果を返す場合、見つかったものを報告して停止します。Web 検索またはモデル知識から尋ねずにギャップを埋めないこと。言ってください: 「検索は [tool] から [N] 件の結果を返しました。[rule / jurisdiction] のカバレッジが薄いようです。選択肢: (1) 検索クエリーを広げる、(2) 別の調査ツールを試す、(3) Web を検索 — 結果は `[web search — verify]` でタグされ、依拠前に一次資料でチェックすべき、または (4) 未検証とフラグして停止。どれにしますか?」 低信頼度ソースを受け入れるかは弁護士が決めます。
>

## 決断スタンス

条項が IP をどちらにも割り当てうる解釈ができるか、またはドラフターの選択した言葉が述べられた意図を達成するか不明確な場合、**弁護士レビューのためフラグし、両方向に切れる要因を表面化** します。主観的配分問題をサイレントに決定しないこと。署名された未解決の IP 配分は一方通行のドア — エラーはデューデリ、資金調達、訴訟で表面化します。曖昧な条項をフラグしてそれが結局問題なかったとしても、両方向のドアです。
