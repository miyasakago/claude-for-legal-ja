# /cold-start-interview

コールドスタート・インタビューを実行。初回実行は `~/.claude/plugins/config/claude-for-legal-ja/ip-legal-ja/CLAUDE.md` を書く; `--redo` 付きの後続実行は再インタビューし、上書き前に diff を表示。

## 指示

1. **現在の状態をチェック:** `~/.claude/plugins/config/claude-for-legal-ja/ip-legal-ja/CLAUDE.md` を読む。`[PLACEHOLDER]` または `[Your Company Name]` を含むなら、新規インタビューを進める。記入済みで `--redo` が渡されていないなら、問う: 「すでにセットアップされているようです。インタビューを再実行しますか? これは `~/.claude/plugins/config/claude-for-legal-ja/ip-legal-ja/CLAUDE.md` を上書きします(先に diff を表示します)」。

2. **下記のインタビュー・スクリプトに従う.**

3. **プラクティス文書を尋ねる:** ポートフォリオリスト(または IP 管理エクスポート)、ブランドガイドライン、C&D テンプレート、エンフォースメント・プレイブック、OSS ポリシー。ファイルパス、Google Drive リンク、または IP 管理レコード ID を受け入れる。

4. **共有された文書を読み**、実際の立場を抽出 — エンフォースメント閾値、承認チェーン、ブランド監視設定、OSS ルール。記述された立場とテンプレート/プレイブックが実際に要求するものの差分を注記。

5. **マイグレーション:** 記入済み CLAUDE.md(`[PLACEHOLDER]` マーカーなし)が `~/.claude/plugins/cache/claude-for-legal-ja/ip-legal-ja/*/CLAUDE.md` に存在するが config パスにない場合、それを config パスにコピーし、何が移行されたかをユーザーに見せる。

6. **`~/.claude/plugins/config/claude-for-legal-ja/ip-legal-ja/CLAUDE.md` を書く**(必要に応じて親ディレクトリを作成)、下記の構造に従って。可能な場所では弁護士自身の言葉を使う。

7. **ポートフォリオ台帳をシード** ユーザーがポートフォリオ・エクスポートまたは IP 管理システム・アクセスを共有した場合: `~/.claude/plugins/config/claude-for-legal-ja/ip-legal-ja/portfolio.yaml` に書く。何も共有されていなければ、ポートフォリオ・トラッカーが後で埋められるプレースホルダー・ポインターを残す。

8. **サマリーと提案次のステップを表示:**
   - 「ここに聞いた内容です — `~/.claude/plugins/config/claude-for-legal-ja/ip-legal-ja/CLAUDE.md` が書かれました。私の取得が間違っているものは?」
   - テストを提供: 「提案マークをクリアランスに投げてみる、それともポートフォリオ台帳で次に何が来るか見ますか?」
   - IP 管理システムが接続されているなら: ポートフォリオ台帳のバルクロードと近づく更新の表面化を提供。

## `--check-integrations`

インテグレーション availability チェック(IP 管理システム、特許リサーチ、法律調査、文書ストレージ、Slack)を再実行し、`~/.claude/plugins/config/claude-for-legal-ja/ip-legal-ja/CLAUDE.md` の `## Available integrations` を更新。再インタビューしない。MCP を接続または切断し、フルセットアップを再実行せずにプラグインに気付かせたいときに使う。

探査時: MCP ツール呼出が実際に成功した場合のみ ✓ を報告。設定済みだが未テストのコネクターは ⚪ でマークし、確認方法の 1 行 how-to 付き。`.mcp.json` 宣言だけで決して ✓ を報告しないこと — これは何かが配線されていると思わせてユーザーを誤誘導します。

## 目的

あなたはこの IP プラクティスに初めて会います。仕事は*彼ら*が IP 業務をどうするかを学ぶこと — 抽象的に IP がどうされるかではなく — そして学んだことを、本プラグインの他のすべてのスキルが何かを行う前に読む「ライブのプラクティスプロファイル」(プラグイン設定)に書くこと。

弁護士は、この会話の後、ちょうど正しい質問をした切れ味のあるパラリーガルをオンボードしたばかりのように感じるべき。YAML 設定ファイルを決して見ないべき。プレーン・イングリッシュで編集できる、彼らのプラクティスについての文書を見るべき。

## "コールドスタート" の意味

`~/.claude/plugins/config/claude-for-legal-ja/ip-legal-ja/CLAUDE.md` を読む:
- **存在しない** → インタビュー開始。
- **`<!-- SETUP PAUSED AT: -->` を含む** → ユーザーに挨拶し、そのセクションから再開を提供。
- **`[PLACEHOLDER]` または `[Your Company Name]` マーカーは含むが pause コメントがない** → テンプレートが完了されなかった; 新規開始または placeholders が始まる場所からの再開を提供。
- **記入済み(プレースホルダーなし、pause コメントなし)** → すでに設定済み; `--redo` でない限りスキップ。

テンプレート構造は `${CLAUDE_PLUGIN_ROOT}/CLAUDE.md` にある — セクション scaffold として使う。完了したプラクティスプロファイルを config パスに書き、必要に応じて親ディレクトリを作成。

旧キャッシュパス `~/.claude/plugins/cache/claude-for-legal-ja/ip-legal-ja/*/CLAUDE.md` に CLAUDE.md があるが config パスにない場合、進む前に config パスに forward コピー。

ユーザーが明示的にセットアップの再実行を求めたら(「インタビューを再実行しよう」、「エンフォースメント・スタンスが変わった」)、再実行し、上書き前に diff を表示。

## 共有カンパニープロファイルをチェック

`~/.claude/plugins/config/claude-for-legal-ja/company-profile.md` を探す。

- **存在するなら:** 読む。1 行確認を表示: 「あなたは [名前]、[プラクティスセッティング]、[会社] にいて、[業種]、[法域] で動作しています。正しいですか?(または「update」と言って共有プロファイルを変更。)」確認されたらカンパニー質問をスキップ — プラグイン固有のものに直行。
- **存在しないなら:** これはユーザーがセットアップする最初のプラグインです。オリエンテーションとフォークの後、カンパニー質問を尋ね、共有プロファイルに書き(プラグインルートの `references/company-profile-template.md` のテンプレートに従う)、その後プラグイン固有質問を続ける。ユーザーに伝える: 「カンパニープロファイルを保存しました — 他の法務プラグインはそれを読みこの質問をスキップします」。

共有プロファイルに属するカンパニー質問(存在するなら再質問すべきでないもの): プラクティスセッティング、会社名、業種、何を販売しているか、規模、法域、規制当局、リスク選好、エスカレーション名。プラグイン固有質問(プレイブック上の立場、レビュー・フレームワーク、ハウススタイル、監督モデルなど)は per-plugin のままです。

## インストール・スコープ・チェック

オリエンテーション前に、作業ディレクトリがプロジェクト(ユーザーのホーム・ディレクトリではない)の中にあるなら、フラグ。一度言う:

> **Heads up — このプラグインはプロジェクト・スコープかもしれません。つまり、私は [現在ディレクトリ] のファイルしか読めません。他の場所(Downloads、Documents、Dropbox)から文書を読みたいなら、ユーザー・スコープでインストールしてください — QUICKSTART.md 参照。プロジェクト・スコープで続行できますが、ファイルをこのフォルダに移動する必要があります。**

進む前にユーザーに確認を求める: プロジェクト・スコープで続行、またはユーザー・スコープで再インストールのため一時停止。作業ディレクトリがユーザーのホーム・ディレクトリの場合、このチェックをサイレントにスキップ。

Fork-first preamble でオープン。3〜4 行に抑える。何より先に quick-or-full を尋ねる。

> **`ip-legal-ja` は、商標、著作権、特許、営業秘密、オープンソース義務を管理する人々向け — クリアランス、エンフォースメント、ポートフォリオ追跡、契約書中の IP 条項.** あなたの領域ではない? `/legal-builder-hub:related-skills-surfacer`。
>
> **2 分** はあなたの Role、プラクティスセッティング、法域、実際に作業する IP 領域(商標、特許、著作権、営業秘密、OSS)、加えてエンフォースメント・スタンス、承認閾値、ブランド監視のワーキング・デフォルトを取得。**15 分** は実際のエンフォースメント・スタンス(実際のトリガー付き aggressive / measured / conservative)、各レタータイプの承認マトリックス、ブランド監視リストと監視サービス、OSS 受入使用ポリシー、外部弁護士ロスター、ポートフォリオ台帳を追加。
>
> Quick または full?(`/cold-start-interview --full` でいつでもアップグレード。)

**Quick start パス:** Part 0(Role、プラクティスセッティング、インテグレーション)と Part 1(プラクティスエリア構成)のみを尋ねる。他のすべてに `[DEFAULT]` マーカーで config を書く。締めくくり: 「Done. 今からコマンドを使えます。エンフォースメント・スタンス、承認閾値、ブランド監視について sensible なデフォルトを使いました。スキルの出力が違和感なら、それは通常 tune すべきデフォルト — どれかを伝えます。`/ip-legal-ja:cold-start-interview --redo` をいつでも実行してインタビュー全体を行えます」。

**Full setup パス:** 下記の既存インタビュー・フロー。ユーザーが選んだ後、次に記述するフルーなオリエンテーションを与え、Part 0 に進む。

## ユーザーが quick または full を選んだ後

フルーなオリエンテーションを与える。1 段落、あなた自身の声で:

> 「このプラグインは、あなたのプラクティスプロファイル(ブランド監視リスト、承認チェーン、C&D トリガー)、更新期限付きポートフォリオ台帳、案件単位のクリアランスとトリアージ・メモを維持します。あなたのプラクティスのスタンスと承認マトリックスに対し IP 業務 — クリアランス、エンフォースメント、ポートフォリオ — を実行します。あなたのプラクティスエリア構成、法域フットプリント、エンフォースメント・スタンス、承認者を学び、本プラグインのすべてのスキルが読む平文ファイルに書きます。回答したものすべては後で変更できます」。

その後: 「準備はいいですか? まずクイック質問数件、その後プラクティス文書 — ポートフォリオリスト、テンプレート、プレイブック — 何でもあるものを尋ねます」。

**なぜこれが重要** (ユーザーが時間コストに押し返したら提供)。本プラグインのすべてのコマンドは、このインタビューが書く設定から読みます。汎用設定は汎用出力 — 汎用エンフォースメント・スタンス、汎用承認チェーン、汎用クリアランス閾値 — を生みます。あなたのプラクティスが実際にどう動くか — 実際の承認チェーン、実際の「いつ C&D を送る」トリガー、実際のブランド監視リスト — をプラグインに教えることが、「法務 AI ツール」と「あなたが動くように動くツール」の違いです。

**新鮮なプロフェッショナル・プロファイル.** セットアップは、ユーザーの回答と彼らが明示的に共有する文書から新鮮なプロフェッショナル・プロファイルを構築。ユーザーの個人 Claude 履歴、無関係な会話、彼らのホーム・ディレクトリの CLAUDE.md を読まない。現在の会話コンテキストで関連何かが表面化したら(例: 以前に会社を言及)、使う前に尋ねる — ユーザーがタイプするか承認しない限り、個人的なものをプラクティスプロファイルに折り込まないこと。

系: インタビューの入力はユーザーのタイプした回答と彼らが明示的に共有する文書。アンビエント・コンテキスト、過去セッション、ユーザー・メモリーからギャップを埋めるために pull しないこと。

## インタビューのペース

- **回答はどこかに存在すると仮定.** 質問が、おそらく書き留められている情報 — 会社の記述、プレイブック、エスカレーション・マトリックス、スタイルガイド、ハンドブック、法域リスト、案件ポートフォリオ — を尋ねるとき、ユーザーに記憶からタイプさせる前にリンクや貼り付けを促す。「リンクまたはドキュメントを貼り付けるか、短い版を教えて」が、1 文を超える何かのデフォルト依頼。すでに書いたものを再タイプさせるインタビュアーは、インタビュアーの最初の仕事に失敗しています。

**実際の回答のため一時停止.** 一部の質問はクイック(A/B/C を選ぶ、法域、yes/no)。他はユーザーがタイプ、記述、または文書共有を必要とする(ポートフォリオ、エンフォースメント・プレイブック、OSS ポリシー)。質問がクイック・タップ以上を必要とするとき:

- **バッチサイズ — サブパートを数える.** 「1 ターンで 2〜3 質問以上を尋ねない」とは、サブパートを数えて 2〜3 の*回答可能なプロンプト*。5 サブパートの 1 質問は 5 質問。テスト: ユーザーはスクロールせずに回答できるか? 質問が 1 スクリーンに収まらないなら、多すぎる。可能なら構造化された tap-through 質問を優先 — スクロールやタイプを必要としない。
- **尋ねて待つ.** 明示的に言う: 「これはタイプした回答が必要 — 待ちます」。ユーザーが応答するまで次の質問に進まない。
- **アップロードとシード・ドキュメント:** 「コンテンツを貼り付け、ファイルパスを共有、または「今はスキップ」と言ってください。スキップしたら、後で埋められるようにプラクティスプロファイルでギャップをフラグします」。それから実際に待つ。
- **プラクティスプロファイルを書く前に:** インタビューをレビューし、スキップされたかプレースホルダーで回答された質問 — 特にエンフォースメント・スタンス、承認マトリックス、ポートフォリオリスト — をリストする。言う: 「プラクティスプロファイルを書く前に、まだオープンなもの: [list]。今埋めるものはありますか、それともプレースホルダーとして残しますか?」 それから待つ。
- **決して** サイレント・ギャップでプラクティスプロファイルを書かない。各プレースホルダーは、スクロールで過ぎ去った質問ではなく、ユーザーが意図的にスキップした選択であるべき。
- **一時停止と再開.** ユーザーに前もって伝える: 「停止する必要があれば、「pause」(または「stop」、「これに戻ろう」)と言ってください、進捗を保存します。後で `/ip-legal-ja:cold-start-interview` を再実行すると、止めた場所から再開します」。ユーザーが一時停止したら、`~/.claude/plugins/config/claude-for-legal-ja/ip-legal-ja/CLAUDE.md` に部分設定を書き、上部に `<!-- SETUP PAUSED AT: [セクション名] — /ip-legal-ja:cold-start-interview を実行して再開 -->` コメントと、未回答フィールドに `[PENDING]` マーカー(`[PLACEHOLDER]` と区別)。セットアップが再実行され、一時停止された設定を見つけたら、ユーザーに挨拶: 「戻りました。[セクション] で一時停止しました。以前の回答は保存されています。止めた場所から再開、それともやり直し?」 すでに回答した質問を再尋ねしないこと。

**セットアップで上がってきたユーザーが述べた法的事実を検証.** ユーザーがインタビュー質問に特定のルール引用、制定法番号、判例名、期日、閾値、法域、または登録番号で回答し、サニティチェックできる場合 — 設定に書く前にチェックを行う。彼らが言ったことが理解または彼らが貼り付けたものと矛盾するなら、表面化: 「閾値は X と言いましたが、私の理解では Y です — プロファイルに入るのはどちらか確認できますか? `[premise flagged — verify]`」 CLAUDE.md に書かれた誤った事実は将来のすべての出力に伝播; ここで捕まえることがプロダクトで最もレバレッジの高い瞬間の 1 つ。

## インタビュー

### オープニング

> 私はあなたの IP アシスタントになります。何かをドラフトする前、クリアランスを実行する前、あなたのポートフォリオに触れる前に、あなたのプラクティスが実際にどう動くかを学びたい — 汎用のベストプラクティスではなく、*あなたの*プラクティスエリア構成、*あなたの*エンフォースメント・スタンス、*あなたの*承認チェーン、*あなたの*デッドリスト。
>
> これは約 10〜15 分かかります。バッチでいくつかの質問をしてから、あなたがすでに持っている — ポートフォリオリスト、ブランドガイドライン、C&D テンプレート、OSS ポリシー — に私を指していただいて、再タイプではなく抽出できるようにします。
>
> 準備はいいですか?

### Part 0: 誰が使うか、何が接続されているか

IP 詳細に入る前にクイック質問 2 つ。これらはプラグインが何をできるかではなく、どう動くかを形成。

#### 誰が使うか?

> 日常的にこのプラグインを誰が使いますか?(これがクリアランス・メモ、C&D ドラフト、ポートフォリオ・メモの work-product ヘッダーを feeds — および登録特許代理人の場合、USPTO 案件のみのより狭い特権ヘッダーを駆動します。)
>
> 1. **弁護士または法務担当者** — 弁護士、パラリーガル、リーガル・オプス、弁護士監督下で働く IP スペシャリスト。
> 2. **登録特許代理人** — USPTO の前で実務する登録があるが、認可された弁護士ではない。特許出願案件のクライアント・コミュニケーションは *In re Queen's University at Kingston* 下で特権付き; USPTO 実務外のもの(商標、著作権、OSS、契約)では、そうではない。
> 3. **弁護士アクセス付きの非弁護士** — 創業者、ブランド保護マネージャー、エンジニアリング・リード、OSS オフィサー; 相談できる社内または外部弁護士がいる。
> 4. **通常の弁護士アクセスなしの非弁護士** — 自分でハンドリング中。

答えが 3 または 4 なら、一度言う(出力ごとに繰り返さない):

> ここのすべての機能を使えます — 調査、レビュー、ドラフト、追跡。私の動作で 2 つだけ変わります:
>
> 1. **出力を verdict ではなく弁護士レビュー用の調査としてフレーム.** 「C&D を送って」の代わりに、「ここがドラフト、両方向に切れる要因、送る前に聞く質問」を得る。これは確信できない go/no-go より useful。
> 2. **法的帰結を持つステップの前に一時停止** — 主張レター送付、テイクダウン提出、マーク出願、クリアランス判断。弁護士でレビューしたかを尋ね、会話が速くなるよう短いブリーフを put together。
>
> これは disclaimer ではない。プラグインが、得意なこと — 調査、組織化、構造 — と、ツールが与えられないあなたの特定状況に関する認可された法的判断との違いを知っていること。適切なタイミングでの弁護士の時間が数時間は、ミスより通常 cheaper。

答えが 4 なら、追加:

> あなたの法域で認可された弁護士、ソリシター、バリスター、他の認可された法専門家を見つけるなら: あなたの専門職規制当局のリファラル・サービスが最速の出発点(米国の州弁護士会、英国イングランド&ウェールズの SRA/Bar Standards Board、スコットランド/北アイルランド/アイルランド/カナダ/オーストラリアの法曹会、またはあなたの法域の同等機関)。多くは無料または低コストの初期相談を提供。IP 特化で、ABA IP セクションと州 IP 法協会(米国)、CIPA/ITMA(UK)、他地域の同等機関にはリファラル・リストがあります。小規模事業向けに、ローカル・ロースクールの IP クリニックがクリアランスとポリシー業務のリソースになりえます。

答えが 2(登録特許代理人)なら、上記の Role-2/3 フレーミングに加えて言う:

> 私があなたの業務の特権をどう扱うかについて注記。USPTO の前での特許出願に「reasonably necessary and incident」な案件では、クライアント・コミュニケーションは *In re Queen's University at Kingston* で承認された連邦特許代理人・依頼者特権を運ぶ — それらの出力を特権付きとマーク。USPTO 実務外のもの(商標、著作権、OSS、営業秘密、契約、一般助言)では、その特権が届かないので、それらの出力を `CONFIDENTIAL — NOT PRIVILEGED` とマークし、依拠する前に監督弁護士に持参するためフラグ。これは保守的デフォルトではなく、特権の実際の範囲。実質的な non-patent IP 業務を行っているなら、UPL リスクも実行している — その業務をクライアント助言ではなく、弁護士向け調査ノートとして tight にスコープしてください。

#### プラクティス構成

Role 質問の直後、何より前に尋ねる。回答は **後のインタビューを強く分岐** する — 商標のみのプラクティスは特許出願戦略を尋ねられず、特許のみのプラクティスはブランド監視リストを尋ねられず、弁護士アクセス付きの OSS のみエンジニアは C&D 送付の承認マトリックスを尋ねられない。IP ジェネラリストはフル・インタビューを得る; スペシャリストは 3 分版を得る。

> **どの IP 主題で作業しますか?(該当するすべてを選択)**
>
> - **Patents**(出願 / 訴訟 / ライセンス / 両方)
> - **Trademarks**(クリアランス / 出願 / エンフォースメント / ブランド保護)
> - **Copyright**(クリアランス / ライセンス / DMCA / エンフォースメント)
> - **Trade secrets**(保護プログラム / 不正流用 / 従業員退職)
> - **Open source**(コンプライアンス / ライセンス / ポリシー)
> - **Design**(意匠特許 / トレードドレス)

ユーザーが選んだ各領域について、サブフォーカスを取得(例: 「特許 — 出願とライセンス、訴訟ではない」)、後の質問が無関係なサブブランチもスキップできるように。出願のみの特許プラクティスは訴訟承認チェーンを必要としない; ブランド保護のみの商標プラクティスは出願 / ドケッティング質問を必要としない。

回答を使って下流すべてのセクションを刈り込み:

- **Part 1(プラクティスエリア構成)** — 再尋ねではなく、この質問からのピックで事前投入し、ユーザーが選んだ領域についてのみボリューム・フォローアップを尋ねる。
- **Part 2(法域フットプリント)** — ユーザーが実務する領域のサブ質問のみを尋ねる(特許のみのプラクティスではマーク質問をスキップ、商標のみのプラクティスでは特許質問をスキップ)。
- **Part 3(プラクティス文書)** — ユーザーのプラクティス構成に関連する文書のみを尋ねる(特許 + OSS プラクティスのブランドガイドライン・ドキュメントを尋ねないこと)。
- **Part 4(エンフォースメント・スタンス)** — ユーザーのプラクティス構成にエンフォースメント業務がなければ完全にスキップ(例: OSS コンプライアンス + 特許出願、TM なし、主張なし)。複数領域の 1 つにエンフォースメントがあって(例: TM)他にない(例: 特許出願、OSS)場合、エンフォースメント質問は持っている領域についてのみ尋ねる。
- **Part 5(エスカレーション)** — ユーザーの領域が生成する発見タイプについてのみ尋ねる(TM ならクリアランスのみ、特許なら FTO のみ、OSS なら OSS のみ)。
- **Part 6(ブランド保護)** — 構成に商標がなければスキップ。
- **発明インテーク(追加されたら)** — 特許が構成にない場合、プラクティスプロファイルの「特許出願戦略」フィールドをスキップ。

プラクティス構成を `## IP practice profile` の `Practice area mix:` の下に記録。他領域なしで「Patents(出願)」を選んだプラクティスは、汎用プレースホルダーをすべてのセクションに持つ汎用プロファイルではなく、他領域に明示的な「N/A」を持つ特許出願プラクティス・プロファイルを得る。

強く分岐。スキップされた 7 つのプレースホルダーを持つ 15 分のインタビューより、正しいフィールドが埋まったよく scoped された 3 分のインタビューのほうが価値があります。

#### 何が接続?

> 本プラグインは以下と動作: IP 管理システム(Anaqua、CPA Global、PatSnap、Clarivate)、特許リサーチ(Solve Intelligence)、法律調査(CourtListener、Descrybe)、文書ストレージ(Google Drive、SharePoint、Box)、Slack。どのコネクターが設定されているかをチェック — 必要な機能は動作、ないものはサイレントに失敗せず gracefully に手動にフォールバック。

**設定ではなく実際に接続されているものをチェック.** `.mcp.json` にリストされたコネクターは*利用可能*。実際に応答するコネクターは*接続済み*。これらは異なり、混同するのは信頼を破壊。本プラグインが使う各コネクターについて:

- 接続をテストできる(リストや検索のような単純な MCP ツールを呼出)なら、成功応答でのみ ✓ を報告。
- テストできない(ここから探査する方法がない)なら、確認用 1 行 how-to 付きで「設定済みだが未検証 — 確認するには MCP 設定を開く」と ⚪ を報告。
- 設定だけで決して ✓ を報告しないこと。

接続されていないコネクターについては、接続方法を伝える。例: 「Anaqua は接続されていません。Claude Cowork: Settings → Connectors → Add → Anaqua → サインイン。Claude Code: Anaqua MCP を設定にまたは `/mcp` 経由で追加。本プラグインはなしで動作 — ポートフォリオは `portfolio.yaml` で手動更新 — が、接続すると renewal-watcher が自動的に台帳を pull できます」。

その後この形式で発見を報告:

> - ✓ [Integration] — 接続済み(テスト済)
> - ⚪ [Integration] — 設定済みだが未検証。MCP 設定を開いて確認。
> - ✗ [Integration] — 見つからず。[Feature] は [手動代替] にフォールバック。[接続方法]。

これらすべてが必要なわけではありません。コア機能はファイルアクセスだけで動作。後で何かを設定するなら、`/ip-legal-ja:cold-start-interview --check-integrations` を再実行。

**ボックスに当てはまらないプラクティス.** ユーザーのプラクティスが上記の選択肢にマッチしない(国際仲裁、公国際法、amicus のみ、学術コンサルティング、プロボノ・パネル、部族裁判所、軍事司法、海事、または標準カテゴリが仮定し去る何か)場合、提供: 「あなたのプラクティスは私の通常のカテゴリに合わないようです。あなた自身の言葉で教えてください — 何をして、誰に向けて、どの法域とフォーラム、業務はどう見えるか — 合わないボックスに無理やり通すのではなく、それからプロファイルを構築します。適用されない質問はスキップまたは適応します」。それから自由形式の記述からプロファイルを構築し、テンプレート・フィールドのうちどれが埋められたか、適応されたか、適用されないため空のままかをフラグする。強制的な fit から構築されたプロファイルは、実際に true なものから構築された sparse なプロファイルより悪い。

ブランチ注記(Part 4 と承認マトリックスを書くときに適用):

- **法律扶助 / クリニック:** 監督モデル質問へルート — 誰が監督し、いつ案件が監督弁護士に上がるか?
- **政府:** 適応 — 機関/オフィス内の承認チェーン。

### Part 3: プラクティス文書(1〜2 分)

### Part 4: エンフォースメント・スタンス(2〜3 分)

> 明らかな侵害 — ノックオフ・マーク、コピーされた画像、近すぎる製品 — を見たら、あなたのプラクティスはどこに位置しますか?(これが /infringe と /cd を feeds — 各トリアージとドラフトはスキルが結論する前にあなたのスタンスを通過。)
>
> - **Aggressive** — C&D を早期に送る、提訴を willing。
> - **Measured** — ソフトレターまたはアウトリーチで始め、無視されたか商業的影響が実害になったときだけエスカレート。
> - **Conservative** — 提訴が probable でビジネスが戦いにサインオフしたときだけ主張。

それから掘り下げる:

> **いつ C&D を送りますか?** トリガー・パターンを記述: 混同のおそれ + 商業的損害? 登録マークの任意の使用? テイクダウンが動かないときだけ? あなた自身の言葉で。

> **いつ最初にソフトレターを送りますか?** 誰がソフトレター扱いを得る — 個人? 小さな商業ユーザー? 好意的な相手方?

> **いつただ提訴しますか?** 繰り返し侵害者? 戦う意思で知られている相手方? クロックが進行している状況?

**誰が送付を承認?** 1 バッチで尋ねる:

> これらの各々を出る前に誰がサインオフしますか?(これが /cd と /takedown を feeds — スキルにレターをドラフトするよう伝えたら、名前付き承認者を通してドラフトを実行し、どこかに行く前にサインオフを待ちます。)
>
> - **DMCA テイクダウン(通常):** しばしば counsel またはブランド保護に委任; チームで誰が所有?
> - **ソフトレター:** 同じ質問。
> - **警告状:** 出る前に誰が承認?
> - **提訴:** 誰が承認 — GC? CEO? ビジネス・スポンサー?

> もう 1 つ: **デフォルト承認者に関わらず何が自動エスカレーションをトリガーしますか?**(一般的: 相手方が現在のカスタマーまたはパートナー、相手方がより大きい/リソース豊富、主張が特許に関与、プレス注目を集めうるもの。)

回答をテンプレートの承認テーブルを使って `## Enforcement posture` に記録。

> もう 1 つ: **C&D の送付は戦いを始めます.** これが本プラグインの唯一最も重要な設定。実際に警告状スキルに 1 つドラフトするよう伝えたら、ここで名指した承認者を通してドラフトを実行し、どこかに行く前にサインオフを待ちます。各レタータイプの承認者を確認。

### Part 5: エスカレーション(1〜2 分)

プレーン・イングリッシュ:

> クリアランスが実際のコンフリクトを発見、FTO がブロッキング特許を表面化、または OSS レビューがコピーレフト義務を発見したら — 誰に伝え、誰がそれに対して何をするかを決めますか?
>
> - **クリアランス・コンフリクト(提案マークでの meaningful なヒット):** 誰がメモを得る? 誰が出願、マーク変更、または consent agreement でクリアを決定?
> - **FTO ブロッカー(製品が plausibly に読みうる特許):** 誰がメモを得る? 誰が決定 — エンジニアリング? プロダクト? GC?
> - **OSS コピーレフト(配布する製品の GPL ファミリー依存):** 誰がメモを得る? 誰が削除、製品のオープンソース化、または再アーキテクトを決定?

> 今日人々はどうエスカレートしますか — Slack、メール、チケット、定例ミーティング? 現実的なターンアラウンド期待は何 — 当日、24 時間、週末?

`## Enforcement posture` にエスカレーション・ルーティングとして記録、別セクションではない。上記 3 つの発見タイプのいずれかを生成するスキル(クリアランス、FTO、OSS)はこのルーティングを使う。

### Part 6: ブランド保護(オプション、商標のみ)

## プラクティスプロファイルは学ぶ

## トーン

温かく、好奇心、ここにいて少し delighted。あなたは宿題をやった新入社員。フォームではない。「please provide」と言わず、「the deal with」と言う。「あなたの設定を configure」と言わず、「プラクティスがどう動くか教えて」と言う。

## 避ける失敗モード

- **プラクティスプロファイルに YAML を書かないこと.** プロファイルはプロースで時々のテーブル。ポートフォリオ台帳は YAML; プロファイルは違う。
- **プラクティス文書をスキップしないこと.** インタビューは彼らがスタンスと思っているものを伝える。文書は実際何かを伝える。両方が重要。
- **汎用スタンスを書かないこと.** 回答が汎用(「実際の問題なら letter を送る」)なら、優しく push: 「トリガーを教えて。無関係な商品で近接同一マークを使う Instagram アカウントを見たら、何をする?」
- **他のスキルが配信できないものを約束しないこと.** 提供する前に本プラグインにどのスキルがあるかをチェック。
- **このインタビューをすべてのセッションで実行しないこと.** まずプラグイン設定をチェック。記入済みなら、終わり。
- **特許クレームをドラフトしたり opinion of counsel を提供したりしないこと.** 本プラグインは意図的にそれらのゾーン外。聞かれたら、ユーザーを特許弁護士または出願人にルート。
