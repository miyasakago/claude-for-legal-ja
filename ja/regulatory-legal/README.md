# Regulatory Counsel プラグイン

規制フィードを監視し、新規制をポリシーライブラリと突合し、ギャップを表面化します。あなたの重要性閾値(materiality threshold)を学習するので、コミッショナーのあらゆるスピーチに反応するようなことはありません。Thomson Reuters Regulatory Intelligence と CourtListener に対応しています。

**すべての出力は弁護士レビューを前提とする下書きです** — 引用付き、フラグ付き、ゲート付きであり、法的結論ではありません。プラグインが作業を行います — 書類を読み、プレイブックを適用し、論点を見つけ、メモを起草します。弁護士がレビューし、検証し、判断します。引用は情報源別にタグ付けされるため、どれが調査ツールから取得され、どれを確認すべきかが分かります。Privilege(秘匿特権)マーカーは慎重に適用され、誤って権利放棄しないようにしています。重要なアクション(filing(提出)、送信、execute(実行))は明示的な確認による gate(ゲート)の背後に置かれます。

## 対象ユーザー

| 役割 | 主なワークフロー |
|---|---|
| **コンプライアンス/規制弁護士** | ウォッチリストのメンテナンス、ギャップトリアージ、ポリシー更新の調整 |
| **プライバシー/プロダクト法務担当者** | 自分の領域に関連するフィルタ済みアラートを受信 |
| **GC(ジェネラルカウンセル)** | 締切付きの重大ギャップに関するエスカレーション受信者 |

## 初回実行: コールドスタート

どの規制機関を監視するかを尋ね、ポリシードキュメントフォルダに接続し、あなたにとって「material(重要)」とは何かを学習します。ウォッチリストを構築し、ポリシーライブラリを索引化します。

```
/regulatory-legal-ja:cold-start-interview
```

## スキル

| スキル | 内容 |
|---|---|
| `/regulatory-legal-ja:cold-start-interview` | コールドスタート: ウォッチリスト + ポリシー索引 + 重要性閾値 |
| `/regulatory-legal-ja:reg-feed-watcher` | 今すぐフィードを確認し、新着情報を報告 |
| `/regulatory-legal-ja:policy-diff [reg]` | 特定の規制変更をポリシーライブラリと突合 |
| `/regulatory-legal-ja:gaps` | 未解決ギャップトラッカー — フラグ済みで未クローズのもの |
| `/regulatory-legal-ja:comments` | 開いている NPRM(規則案告示)のコメント期間をレビュー、意思決定を記録、締切を追跡 |
| `/regulatory-legal-ja:policy-redraft` | ギャップを解消するためのマークアップ付きポリシー修正案 — 内部レビュー用の初稿であり、ソースドキュメントへの直接編集ではない |
| `/regulatory-legal-ja:matter-workspace` | 案件ワークスペース管理(マルチクライアントの私的実務のみ) — new, list, switch, close, none |
| **gap-surfacer** *(リファレンス)* | `/gaps` と `/comments` が読み込む共有のギャップ/コメントトラッカーフレームワーク |

## インタラクティブスキル vs. スケジュールド・エージェント

上記のスキルはあなたが呼び出したときに動作します — 案件作業中に使うものです。下記のエージェントはスケジュールで動作します — あなたが見ていない間に動く対象を扱います。

| エージェント | 監視対象 | デフォルトの実行頻度 |
|---|---|---|
| **reg-change-monitor** | 規制フィード — コールドスタートで学習した重要性閾値でフィルタし、ノイズではなくシグナルになるダイジェストを投稿 | 週次(規制環境が活発なら日次) |

## コネクターと引用検証

**まず調査ツールを接続してください — 引用ガードレールはこれに依存します。** 接続しないと、すべての引用は `[verify]` タグ付きになり、各成果物の上のレビューアー注記には情報源が未検証であると記録されます。プラグインはどちらでも動作しますが、調査ツールが接続されているとより多くの検証を肩代わりします。

このプラグインのリーガルリサーチコネクターは単なるデータソースではなく、検証済み引用と確認が必要な引用の違いそのものです。接続された調査ツール経由で取得した引用は情報源タグ付きで、追跡可能です。モデルの知識やウェブ検索からの引用は `[verify]` または `[verify-pinpoint]` タグ付きで、依拠する前に primary source(一次情報源)と照合すべきです。プラグインは引用を階層化するため、検証時間を重要なところに振り向けられます。

## 統合(Integrations)

`.mcp.json` に汎用コネクター群を同梱しています:

- **Slack** — メッセージ検索、チャンネル閲覧、議論の検索
- **Google Drive** — ドキュメントの検索、閲覧、取得

Thomson Reuters Regulatory Intelligence コネクターは、パートナー URL が利用可能になった時点で追加できます。フォールバックとして規制機関の直接 RSS/メールが使えます。

## 前提条件

オーナー通知(ギャップ割当、期日リマインダー、NPRM アラート)には Slack MCP サーバーが必要です。なくてもギャップトラッカーとコメントトラッカーは動作します — 通知は投稿されず、スキルはステータスレポートでゲート未通過の項目をフラグ付けします。

## 学習のしくみ

`~/.claude/plugins/config/claude-for-legal-ja/regulatory-legal-ja/CLAUDE.md` のプラクティスプロファイルは静的ではありません — プラグインを使うほど改善されます。出力にチューニングすべきデフォルトが使われた場合、スキルがそれを告げます。`reg-change-monitor` エージェントは規制フィードを監視し、ポリシーライブラリと照らして変更をフラグ付けします。セットアップを再実行する、ファイルを直接編集する、またはスキルに新しいポジションを記録するよう伝えることができます。

## 注記

- 重要性フィルタが価値の本体です。「技術的にはすべての規制変更」を、ここで実際に重要なものに絞り込みます。
- ポリシー diff は索引化されたポリシーと比較します。ポリシーライブラリが接続されていない場合は、貼り付けた内容に対して diff を実行します。
- これは privacy-legal の `reg-gap-analysis` の自動化版です。組み合わせて使うのがおすすめです — こちらは監視し、あちらは深掘りします。

## 設定

設定は `~/.claude/plugins/config/claude-for-legal-ja/regulatory-legal-ja/CLAUDE.md` に保存され、プラグイン更新後も残ります — セットアップは一度実行するだけです。
